## 更新內容

Textus 1.2.0 讓 Textus AI 能做的更多，編輯器也更好用。Textus AI 可以在所有服務商下聯網搜尋並註明出處，一鍵深度思考，邊寫邊配圖，讀取資料夾裡的長檔案、PDF、Word、幻燈片、表格和圖片，呼叫 MCP 伺服器提供的工具，從你拒絕的修改中學習，也能一鍵徹底關閉；它的修訂邊寫邊出現在文件裡，落在它要改的那一段，你自己改動後也不會失效，頁邊再擁擠，卡片也始終在對應文字旁邊。服務商新增豆包和 MiniMax。編輯器可以開啟整個資料夾，只儲存你改過的部分，支援 wikilink 和指向標題的連結，能把 Word 文件作為 Markdown 開啟，在原處展開連結供編輯，自動補全括號和引號，超長文件也依然流暢。設定新增搜尋框；Textus 支援螢幕閱讀器、純鍵盤操作和高對比度，也能在較舊的 Windows 電腦上執行。

### 新增

- 開啟 **設定 › 通用 › 應用 › 在背景保持執行**（預設關閉）後，關閉最後一個視窗時 Textus 仍保持執行，並在通知區域、系統托盤或選單欄顯示圖示。圖示選單裡有 **開啟 Textus**（恢復你之前開啟的文件）和 **退出 Textus**；關閉該設定後圖示立即消失。沒有視窗開啟時，Textus 不保留任何已載入的頁面，也不在背景執行任何任務。(#244)
- 用 **檔案 › 開啟資料夾…** 在側邊欄開啟整個資料夾：在其中開啟文件時，檔案樹保持以它為根；資料夾會隨會話恢復，也會出現在 **檔案 › 最近開啟** 中；**檔案 › 關閉資料夾** 讓檔案樹恢復跟隨當前文件。(#152, #79)
- 開啟 Word 文件（`.docx`）——無論是在 **檔案 › 開啟…** 中選擇、拖到視窗上，還是由檔案管理器交給 Textus——都會生成一個同名、尚未儲存的 Markdown 新文件：標題、帶編號的列表、表格、粗體、斜體、連結、腳註和圖片都會帶過來，而只是看起來像 Markdown 的文字（如 `*`、`#` 或 `$5`）仍保留為文字。一條不打擾的提示會說明部分格式可能有差異。第一次 **儲存** 時會建議在 Word 檔案旁邊存為 `.md` 檔案，並像貼上的圖片一樣，把圖片移入 **設定 › 圖片** 指定的圖片資料夾；Word 檔案本身不會被改動。(#296)
- 在側邊欄 **檔案樹** 標籤頂部的搜尋框裡搜尋已開啟資料夾中的檔名——先列文件，再列其他檔案，也可以用搜尋框旁的篩選只看文件——跳過 `.gitignore` 排除的內容和 `node_modules` 等資料夾：輸入即篩選，`↑`/`↓` 移動，`Enter` 開啟，`Esc` 清空；`Ctrl/⌘ + Shift + O` 可直接跳到這裡（可在 **設定 › 快捷鍵** 中修改）。(#196)
- 支援 Obsidian 的 wikilink——`[[Note]]`、`[[Note|text]]` 和 `[[Note#Heading]]`——作為連結：`Ctrl/⌘ + 點選` 會從同一資料夾或整個 vault 中開啟對應筆記（若指定了標題，則跳到該標題）；儲存時它們和行首的 `#tags` 一樣按原樣寫入，不再變成 `\[\[Note]]` 和 `\#tag`。(#234)
- `Ctrl/⌘ + 點選` 指向其他檔案中某個標題的連結（如 `[see](./notes.md#heading)`）時，會在新標籤頁、或該檔案已開啟的標籤頁中直接跳到那個標題，而不是檔案開頭。(#233)
- Textus 恢復上次會話，或你從 **檔案 › 最近開啟** 中選擇文件時，只要檔案之後沒有改動，游標會回到你上次離開的位置，並滾動到那裡；關閉 **設定 › 通用 › 啟動時恢復上次會話** 時，文件仍像以前一樣從開頭開啟。(#218)
- 新增 **下一個標籤頁** 和 **上一個標籤頁** 快捷鍵：所有平台上為 `Ctrl + Tab` 和 `Ctrl + Shift + Tab`（Mac 上另有 `⌘ + Shift + ]` / `⌘ + Shift + [`）；新增 **標題 1** 到 **標題 6** 的快捷鍵，與 Typora 一樣為 `Ctrl/⌘ + 1` 到 `6`，並顯示在 **格式** 選單中對應項旁邊；還有 **正文** 的快捷鍵，預設未繫結。這些都可以在 **設定 › 快捷鍵** 中修改，**還原** 可把改過的恢復原樣；該頁現在也列出無法修改的快捷鍵，如儲存、縮放、粗體和斜體。如果某個操作已經佔用了這些按鍵，它會保留原按鍵，相應的標題級別則預設不繫結。(#214)
- 新增 **設定 › 編輯與外觀 › 介面文字大小**——90%、100%、110% 或 125%——可放大或縮小側邊欄、大綱、標籤頁、AI 面板及其獨立視窗、選單和設定中的文字，文件本身的縮放保持不變。(#150)
- 程式碼塊的語言選擇器旁新增 **複製** 按鈕，可複製整塊程式碼；程式碼塊還可以顯示行號，在 **設定 › 編輯與外觀 › 程式碼塊顯示行號** 中開啟。開啟後長行改為橫向滾動而不再折行，讓每個行號始終對齊它的那一行。按鈕和行號都不會出現在 PDF、匯出檔案或列印稿中。(#233)
- 按 **設定 › 編輯與外觀 › 顏色程式碼前的色塊**（預設關閉）的設定，在顏色程式碼前顯示一個小色塊：**僅在程式碼中** 會在表示顏色的行內程式碼（如 `#0af` 或 `rgb(0 128 255)`）和程式碼塊裡的顏色字面量前顯示；**全文** 還會在段落、標題、列表、引用或表格正文中任意位置的六位或八位十六進位制顏色值和顏色函式前顯示，如 `#ff8800`、`hsl(120 50% 50%)` 或 `oklch(70% 0.1 150)`。正文中的短程式碼、`#cafe` 這樣的標籤、`#234` 這樣的 issue 編號、`red` 這樣的顏色名以及連結保持原樣；色塊不屬於文字，因此不會被儲存、複製或列印，也不會進入匯出檔案。(#146)
- 新增 **設定 › 編輯與外觀 › 圖表引擎**：預設仍是 Mermaid，也可以選擇 [Pele](https://pele.run)。Pele 繪製同樣的 ` ```mermaid ` 程式碼塊，速度更快、下載體積小得多，切換外觀或主題時無需重繪，但它有自己的排版方式，也缺少少數功能，例如標籤中的 HTML。Pele 畫不了的圖表會交給 Mermaid 繪製；編輯器、分欄檢視和所有匯出都使用你選擇的引擎。(#242)
- 新增 **深度思考** 按鈕，即 AI 面板及其獨立視窗中聯網搜尋旁邊的燈泡，讓模型在回答前先把請求想透——更慢、花費也更多，適合難題和長篇改寫。它會一直保持開啟，跨對話、跨文件都有效，直到你再次點選；只有支援深度思考的模型才會顯示。快速提問則會要求模型快速作答。
- 模型思考時，回覆上方顯示“思考中 · 8 秒”，結束後顯示“思考了 12 秒”；這一行預設收起，點選即可展開檢視推理過程（包括 Gemini），前提是服務商提供推理內容。推理過程不會隨對話儲存。每個模型支援哪些思考引數現在取自 [models.dev](https://models.dev)；服務商拒絕這些引數時，會去掉它們重新傳送請求。
- Textus AI 可以讀取專案資料夾中的 PDF、Word、PowerPoint 和表格檔案並搜尋其中的文字；使用能識別圖片的服務商時，還能檢視其中的 PNG、JPEG、GIF 和 WebP 圖片，每張最大 6 MB。(#261)
- **設定 › Textus AI** 的服務商中新增 **豆包（火山引擎）**（英文介面為 Doubao (Volcengine)），由火山方舟提供：對話使用 Doubao Seed 2.1 Pro，可以讀取附帶的圖片並編輯文件；補全和語法檢查使用關閉思考的 Seed 2.1 Turbo。請在火山方舟控制檯建立 API Key 並開通這些模型。(#263)
- 服務商中新增 **MiniMax**，分為 **MiniMax（國內版）** 和 **MiniMax（國際版）**，因為兩個平台只接受各自的 Key：對話和編輯使用 MiniMax-M3，補全和語法檢查使用 M3.1 Flash，生成圖片使用 image-01，共用同一個 Key。
- 從你的修訂選擇中學習：當你在多次建議中反覆拒絕同一類修改——把「」改成“”、把一個詞換成另一個、拆分句子、加上牛津逗號——審閱結束後，Textus AI 會提議把它記為一條寫作要求，並提供 **記住**、**暫不** 和 **不再詢問**。選擇記住後，它會儲存在記憶頁的 **AI 記住的** 下，你可以刪除；Textus AI 每天最多詢問一次，不經你點選不會儲存任何內容。只會在這台電腦上記錄你採納或拒絕的修改型別，且從不傳送出去。
- 在 **設定 › Textus AI** 中選擇 **圖片模型** 後，Textus AI 就能為文件配圖——支援 OpenAI、Google Gemini、豆包（火山引擎）、阿里通義千問、智譜 GLM、矽基流動或相容 OpenAI 的介面；預設為 **無**，對話已在使用的服務無需再填一個 Key。在寫作或修訂模式中提出要求，或右鍵段落選擇 **為這段配圖**：圖片會作為建議出現在原處，只有採納後才會按 **設定 › 圖片** 的設定儲存到圖片資料夾或上傳到圖床，拒絕則不留任何痕跡；服務拒絕某個描述時，AI 面板會顯示原因。(#194，部分想法來自 #221)
- 所有 AI 服務商都能聯網搜尋：能自行搜尋的模型（OpenAI、Claude、Grok、OpenRouter、Groq、通義千問、智譜 GLM）使用自帶的搜尋；其餘的——DeepSeek、Gemini、Mistral、Kimi、本地模型和自定義介面——由 Textus 透過 **設定 › Textus AI › Textus AI 對話 › 聯網搜尋** 下的 **搜尋服務** 來搜尋：**自動** 會使用你已有的 DeepSeek、智譜或 Kimi Key，也可以選擇 Bocha、Tavily、Brave Search 或 Exa 並填寫各自的 Key，或使用你自己的 SearXNG 伺服器。你給出網頁或 PDF 的地址時，Textus AI 也能讀取——僅限公網，絕不會訪問你的電腦或區域網；沒有可用的搜尋方式時，聯網搜尋按鈕上會顯示紅點。(#278)
- 回覆引用的網頁會列在回覆下方，所有服務商、整段對話都統一按 [1]、[2] 編號；點選即可在瀏覽器中開啟。用到網路資料的建議，其卡片上有 **把來源加為腳註**，採納時會把來源作為 Markdown 腳註新增到文件末尾。(#278)
- 設定的分類上方新增搜尋框：輸入一個詞，所有頁面中匹配的設定項會按頁面列出——包括名稱、分組標題、更多主題和關於 Textus、快捷鍵列表，以及 **?** 背後的說明——不區分大小寫、重音和全形字母。`↑`/`↓` 移動，`Enter` 或點選會開啟該設定所在頁面並短暫突出顯示它，`Esc` 清空；設定開啟時按 `Ctrl/⌘ + F` 可跳到搜尋框。
- 用視窗欄最右側的按鈕可以徹底關閉 Textus AI，按鈕圖示由機器人改為應用圖示中羽毛筆的剪影：右鍵可暫停 Textus AI 一小時或將其關閉；關閉期間羽毛筆上會顯示一道斜線，點選可選擇重新開啟；暫停會自動結束。**設定 › Textus AI › 開啟 Textus AI**（預設開啟）、可在 **設定 › 快捷鍵** 中設定的快捷鍵，以及 iPhone 上的選單也都能開關它。關閉期間，從 Textus 啟動那一刻起，不會向任何 AI 服務傳送任何內容：沒有補全、語法檢查、對話或記憶；AI 面板、快速提問和右鍵選單中的 AI 項都會隱藏，正在生成的回覆也會停止。已經提出的修改仍可採納或拒絕；各項功能保留各自的設定，待 Textus AI 重新開啟時沿用。(#196)
- 括號和引號自動補全，與 Typora 一致：輸入 `(`、`[`、`{`、引號，或用中文、日文輸入法輸入 `（`、`【`、`「`、`“` 時，會在游標後補上對應的閉合符號。再輸入閉合符號會直接跳過它，緊接著開符號按 Backspace 會將兩者一起刪除；選中文字時則把這對符號包在文字兩側。在程式碼、公式或網址中、單詞前，以及作為撇號使用時（如 "don't"）不會補全。可在 **設定 › 編輯與外觀 › 補全 ()、[] 和 “”** 中關閉。
- 游標位於連結上時顯示其 Markdown 原始碼，與 Typora 一致：點選連結，或用方向鍵移到連結上，`[text](url)`——或 `[text](url "title")`、`[text][ref]`、`<https://…>`、裸網址——就會展開，文字和地址都可以編輯；游標移開後它又變回連結，並帶上你的修改，如果已不再是連結則變為普通文字。`Ctrl/⌘ + 點選` 仍可開啟連結；只是看了看的連結會原樣儲存，改過的則按你輸入的內容儲存。

  - 把檔案或資料夾拖到另一個資料夾上即可移動，已開啟的文件會跟著移到新位置；
  - **排序** 可按名稱或修改時間排列檔案樹。
  - 不會覆蓋任何內容：已被佔用的名稱會被拒絕。
- 視窗欄開頭新增側邊欄按鈕：Mac 上緊挨紅綠燈按鈕，全屏時位於紅綠燈所在的角落；Windows 和 Linux 上位於選單按鈕旁邊。側邊欄滑入滑出時，按鈕位置保持不動。
- 用 ChatGPT 訂閱自帶的圖片額度生成圖片：用 ChatGPT 登入後，**設定 › Textus AI › 圖片服務** 中會出現 **OpenAI · ChatGPT 訂閱（實驗性）**。它使用 ChatGPT 自家應用所用的服務，而非公開 API，因此可能隨時失效；OpenAI API Key 仍照常可用。
- 修改文件中已有的圖片：右鍵圖片，選擇 **讓 Textus AI 修改這張圖…**，再說明怎麼改。新圖片會作為建議出現在原處；採納後，Textus 會詢問是否把舊檔案移到廢紙簍，除非你同意，否則保留舊檔案。
- **設定 › Textus AI** 新增 **每次最多生成幾張圖**：說明你要幾張，Textus AI 就生成幾張，但不超過這個數（預設兩張）。未說明數量時生成一張，或者為較長內容中適合配圖的每個部分各生成一張，並先說明配在哪裡。
- **設定 › 擴充套件** 彙集你為 Textus 新增的內容，各佔一個標籤頁：主題（主題庫和你自己的主題）、Skill 和 MCP。每一項都是一張帶開關的卡片。

### 改進

- **學術潤色**（`/academic`）現在也適用於基金申請書，而不只是論文：除了正式措辭、單位和引用格式，它還會刪去套話式開頭、誇大其詞、空洞的強調詞和言過其實的動詞，讓每個論斷不超出證據所能支撐的程度，保留證據所需的限定語，對照可行性檢查申請書的研究目標（NSF、NIH、國自然），並讓所有數字、公式、引用和引用鍵保持原樣。每處修改都以建議的形式給出，回覆中附一份簡短的修改說明；它改進的是寫作本身，而不是用來規避 AI 使用宣告的工具。改編自 [academic-humanizer](https://github.com/AIScientists-Dev/academic-humanizer)（MIT），後者基於 [humanizer](https://github.com/blader/humanizer)。
- 只儲存你編輯過的塊：其他段落、標題、列表和表格都按檔案中原來的樣子寫回，因此同時用 Git 管理或在其他應用中編輯的檔案，只會出現很小的 diff，而不會被整體重新格式化。(#234)
- Textus AI 還在寫修訂稿時就逐句顯示改寫：每句寫好就出現在原處，被替換的原句以刪除線顯示在旁邊，保留不變的句子原樣不動；不再是整段劃掉、新文字跟在後面流式輸出、直到最後才逐句排開。寫完時不會有任何跳動；**停止** 會保留已寫完的句子，段落其餘部分維持原樣。(#243)
- 修訂動畫更平和、更統一：新文字、刪除線和 ✓ / ✕ 以相同節奏淡入，快速相繼出現而非逐個登場，沒有模糊或彈跳；採納的文字在原處從綠色漸漸褪去，而不是瞬間切換。(#243)

- 審閱批註隨 Textus AI 寫出而逐條出現在頁邊，回覆下方顯示“正在寫批註…”，而不是全部寫完後一次出現。批註和圖片現在指明所在段落而不是引用原文，花費更少，每次都能找到對應位置；設定了寬度的圖片也可以重做。
- 編輯 Textus AI 建議修改的文字時，不再丟棄該建議。只要某處修改所改寫的句子保持原樣，它就仍然有效；你改過句子的那處修改會被擱置（改回去又會恢復），採納時只寫入這些修改，你的編輯保持不變。修訂還在流式輸出時也是如此。
- Textus AI 的編輯會落在它要改的地方：它看到的文件與編輯器中的一致，按段落劃分——列表或引用是一塊，表格是一塊，圖片是一塊——每處編輯都指明要改哪一塊，因此會放在那裡，而不會落到文件其他地方相同文字的副本上。段落內改動的幾個詞只在該段落內查詢。
- 對 Textus AI 改寫中的圖片、表格、程式碼塊或公式，按編輯器的方式加以區分，因此每個都作為一處修改來決定，改寫中與文件中保持一致。
- 批註和修訂卡片較多時，仍會留在相關文字旁邊。擁擠段落的卡片會裁剪到與其所在行等高的空間，小改動只顯示變化的詞，批註多於行數時合併為一個“8 條批註”標籤。點選任意一個即可檢視完整內容。
- 點選頁邊的批註或修訂卡片，或用底部的欄跳到某一條時，卡片和相關文字會一起高亮，文字以一次平滑滾動進入視野，無論有多遠。一組批註只畫一條連線。
- AI 連續提出幾處編輯時，AI 面板把它們顯示為一張卡片，而不是一列卡片：每處編輯一行，各有采納和拒絕；理由相同時只寫一次；另有“全部採納”/“全部拒絕”。較長的列表只顯示前幾行，其餘收在“展開其餘 N 處”後面；所有編輯都決定後，卡片摺疊成一行狀態。

### 修復

- 儲存在隱藏資料夾（如 `~/.notes`）中的文件，其圖片現在可以正常顯示，以前會顯示為“Textus 無法顯示的格式”。
- ChatGPT 生成的圖片按要求的比例繪製：以前要正方形卻得到寬圖。
- 翻譯後的標題在等待審閱時，新文字不再帶有 Markdown 的 `#`；審閱批註中的 **粗體** 術語顯示為粗體，而不是夾在星號之間。
- 聯網搜尋較久的 Claude 回覆能完整結束，不再中途截斷；帶引用的回覆也不再在每處引用處斷成短行。(#278)
- 行內補全使用游標周圍正文的語言，正文太少無法判斷時使用介面語言，不再在圖表或程式碼塊之後偶爾換成另一種語言；游標附近只有圖表時，輸入過程中不再給出建議。(#256)
- 你輸入其他內容、開始用輸入法輸入，或 Textus AI 顯示建議時，補全會立即消失；你輸入的正是補全的開頭時，補全則相應縮短；你已經繼續往下寫之後才到達的補全不再顯示。(#256)
- 保留引用式連結 `[text][ref]` 及其 `[ref]: url` 定義，以前編輯後第一次儲存會把它們變成行內連結並刪除定義。(#234)
- 以 `---` 分隔線開頭的檔案中，列表和引用會被識別為列表和引用，而不是純文字（以前編輯後會帶著轉義符儲存）。(#245)
- 編輯段落時保留連結文字中的方括號，如 `[Tech [Episodes]](…)`，不再儲存成讀回來會變成公式的形式。(#245)
- 編輯段落或把其中某個詞設為粗體時，包住粗體或斜體文字的連結保持為一個連結，不再被儲存成三個連結。(#245)
- 刪除或設定其中文字的格式後，粗體和斜體文字按顯示的樣子儲存：刪除最後一個詞不再在檔案中留下多餘的 `**` 或 `*`；緊挨粗體文字設為粗體的詞，或並排的兩個程式碼片段或公式，不再連在一起。(#245)
- 以 `# `、`- ` 或 `1. ` 開頭的一行文字，在其後的詞被刪除或設為粗體後，仍儲存為文字，而不是標題或列表項。(#245)
- 刪除某行唯一的詞或某行以 `<br>` 結尾時，段落保持完整；段落末尾的換行不再被儲存為多餘的反斜槓。(#245)
- 在文件其他位置編輯時，檔案中的 `<br>` 標籤保持你寫的原樣。(#245)
- 刪除列表項的第一行時，其餘內容仍留在該項中；列表項中的分隔線保持為分隔線；`## Item #` 這類標題結尾的 `#` 得以保留。(#245)
- 從子資料夾中開啟文件時，檔案樹保持原位，已展開的資料夾仍然展開——以前會跳進那個子資料夾。(#152)
- 跨多行的建議只給文字著色，不再給其中的換行著色：硬換行和兩段之間的空行不再在行尾或空行上出現一小截綠色，指標懸停時也不會；硬換行之後的改寫不再多劃掉一個字元，也不再顯示為一整塊。(#243)
- 在 **修改在正文，原文在頁邊** 和 **只看結果，不加標記** 模式下，改寫把多段合併為一段時，正文中不再留下空白；被擠到遠離對應段落的頁邊卡片，其連線不再作為雜亂的線條畫在卡片旁邊：這類卡片的連線在指向或跳到它時才顯示。(#258)
- 兩張貼上的圖片在同一時刻儲存時（例如在兩個視窗中），各自儲存為獨立的檔案，後一張不再覆蓋前一張。(來自 #221)
- 用 **檔案 › 另存為…** 把文件存到其他資料夾時，圖片會一起帶過去，複製到 **設定 › 圖片** 為新檔案設定的圖片資料夾中，新檔案不再缺圖；在 macOS 上，新文件中貼上的圖片在首次儲存時也會移到文件旁邊，而不是留在 Textus 自己的資料夾裡。(來自 #221)
- HTML 匯出儲存到文件資料夾以外時，本地圖片會嵌入頁面，而不是指向不存在的檔案；PDF 匯出的每張圖片都從其檔案讀取，不再有空白圖片。(來自 #221)
- AI 面板獨立視窗中的歷史記錄、新對話和置頂按鈕，現在與停靠面板中的大小和粗細一致，不再被擠成細條並顯得發淡。(#287)
- 遵循系統的高對比度設定：開啟 **增強對比度**（macOS）或高對比度主題時，次要文字與正文一樣深，Textus AI 的新文字除著色外還加下劃線；在 Windows 的 **對比度主題** 下，卡片、各種欄以及選中的標籤頁或行會以系統顏色保留邊框，不再隨陰影和著色一起消失。
- 只有在系統要求減少動態效果時，審閱條的出現和消失以及指標下頁邊卡片的移動才改用淡入淡出，與其他介面一致。
- 在預設的淺色和深色外觀中，灰色和彩色文字的對比度至少為 4.5:1（WCAG AA）：引用、程式碼高亮、建議修改中被劃掉的原文、側邊欄中的資料夾名和搜尋結果、AI 面板的標籤頁、建議卡片的 **已拒絕**，以及深色外觀中的紅色按鈕。
- 首次啟動時關閉視窗，無論是透過關閉按鈕、`Alt + F4`、`⌘ + W` 還是視窗管理器（如 niri 的關閉視窗），未儲存更改的提示現在顯示在語言歡迎頁前面；以前提示被畫在歡迎頁後面，視窗因而沒有關閉，看起來像關閉操作被忽略了。
- 在 WebView2 較舊的 Windows 上（許多 Windows 10 電腦都是如此），設定和應用的其他對話方塊能適應較矮的視窗：標題和關閉按鈕留在螢幕上，頁面在內部滾動，而不是對話方塊超出視窗上下邊緣且無法滾動。(#260)
- 粗體、斜體和刪除線中的行內程式碼得以保留：在粗體中輸入 `` `code` `` 現在會變成程式碼，而不是保留帶反引號的文字；`Ctrl/⌘ + B` 能把含有程式碼的選區設為粗體；在程式碼兩側重新輸入刪掉的 `**` 能恢復粗體；以粗體、程式碼或公式開頭的貼上內容保留其格式，而不是變成純文字。(#318)
- 較長的表頭會像正文單元格一樣折成多行，而不是保持一行把表格撐寬，或在設定了列寬時以及列印和匯出中壓到下一列上；負責人這類短表頭保持完整。(#318)
- 輸入 Markdown 的效果與其寫法一致：`* ` 開始無序列表、`***` 生成分隔線，與 `- ` 和 `---` 相同；`####### ` 保持為文字；在標題中按 Shift+Enter 會換行，而不是在儲存時變成下劃線式標題，在程式碼塊中則新增一行；在行內程式碼中按 Enter 會拆分該行；Tab 和 Shift+Tab 對程式碼塊中選中的行縮排和取消縮排，而不是替換它們或跳出編輯器；wikilink 之後輸入的文字不再併入其中；在文件開頭或末尾的表格中，從任意單元格都能用方向鍵離開表格；貼上到表格單元格的多行內容留在該單元格中，不再覆蓋旁邊的單元格。(#320)
- 在 WebView2 較舊的 Windows 上（如不更新的 Windows 10 電腦），介面完整顯示：關閉狀態的開關重新有了軌道，卡片、設定分組和審閱條有了背景和邊框，建議的編輯有了紅綠色；編輯器的右鍵選單、查詢欄和 **插入表格** 對話方塊在正確的位置開啟，不再偏到一邊；側邊欄可以重新調整寬度；AI 面板的空白狀態不再閃爍；原始碼模式居中顯示；帶連結的 Mermaid 圖表能正常繪製。(#260)
- Textus AI 獲取的所有地址——從網上讀取的頁面，以及圖片服務以連結形式留下的圖片——都經過同樣嚴格的檢查，因此都無法透過換一種寫法的地址訪問這台電腦或你的區域網，例如攜帶私有 IPv4 地址的 IPv6 地址、6to4 或 NAT64 地址，或 `printer.local` 這樣的名稱。(#327)
- 更多 Markdown 編輯行為符合預期：`Ctrl/⌘ + B` 和 `Ctrl/⌘ + I` 又能去掉詞語的粗體和斜體，在剛輸入的內容末尾按下時會結束格式、後續文字恢復普通，與 Typora 一致；輸入 `[text](url` 後，越過自動補上的 `)` 時它就變成連結；Tab 和 Shift+Tab 不會再把焦點移出正文；格式 › 無序列表或有序列表可以切換列表型別；在標題開頭按 Backspace，無論哪一級都會變成正文，在提示框第一行按則保留提示框（再按一次變成普通引用）；`~~~` 開始程式碼塊，第一行的 `---` 開始 front matter，`1) ` 開始列表，而 `===` 保持為文字；手動輸入的 HTML、`<br>` 和腳註引用按輸入的樣子儲存；在空格前按 Enter 不再儲存出 `&#x20;`；← 和 → 一樣在行內 HTML 上每次移動一個字元；粗斜體按一次方向鍵即可展開；刪除程式碼外粗斜體的最後一個詞不再讓兩種格式都丟失；編輯過的段落保留兩個空格的換行，表格中的中日韓文字能對齊；Word 列表貼上後仍是列表，在行中間貼上的標題保留其 `#`；設定 › 快捷鍵會指出某個按鍵屬於哪個固定快捷鍵。(#329)
- AI 面板滑入頁面旁邊時，視窗其他部分不再移動，無論側邊欄是否開啟。以前在 Mac 上開啟它會把側邊欄和正文推到一邊，滑動結束時又彈回原位。在較小的視窗中，它還會帶著陰影蓋在頁面上（與全屏時不同），之後開啟側邊欄會改變它並重新播放滑入動畫；現在它始終留在頁面旁邊，寬度保持不變。
- 在 Mac 上用觸控板滑動到側邊欄盡頭或越過標題欄時，視窗保持不動，不再整頁彈動。文件本身在兩端仍有回彈，短文件也一樣。
- 禪模式只隱藏正文以外的所有內容並淡化其他段落，視窗保持原樣，不再同時進入全屏。
- 設定中比按鈕更寬的下拉選單（如 **圖片模型** 的列表）留在視窗內，不再超出視窗右邊緣。
- 在 Mac 上，**編輯 › 全選** 會選中文件或你所在的文字框，而不是在游標不在兩者中時選中整個視窗及側邊欄的筆記。
- `~~` 和 `==` 在你輸入閉合符號之前保持輸入的樣子，與 Typora 一致，而不是畫出一個空的刪除線或高亮，把兩個波浪號顯示成四個。`~~text~~` 和 `==text==` 仍會變成刪除線和高亮。
- 在 Mac 上，手指在文件頂部或底部離開觸控板時，文件立即回彈，而不是隨滑動慣性滑行並在那裡停頓片刻才鬆開。帶慣性衝到盡頭的滑動只回彈一次。
- Textus AI 建議的圖片按採納後的寬度顯示在正文欄內，而不是按圖片服務生成的原始尺寸顯示，以前在採納之前會遠遠超出頁面。
- 對選區按 **⌘B** 或 **⌘I** 後文字保持選中，與 Typora 一致，因此再按另一個可得到粗斜體，再按同一個則取消，而不是選區消失、下一次按下在游標處開啟空的格式。在按下前剛用鍵盤做出的選區按其顯示的範圍生效；在 Mac 上雙擊粗體或斜體詞會選中該詞，而不是什麼都不選或選中旁邊的詞。

- 拖到視窗上的檔案在新標籤頁中開啟，而不是替換你正在閱讀的文件；只有空的未命名標籤頁會讓位給它。
- 在 Windows 和 Linux 上，視窗內繪製的選單中的 **檔案 › 關閉視窗** 能關閉視窗了，以前沒有任何作用。(#345)
- 在決定上一個請求之前就傳送新請求時，Textus AI 會基於你看到的文件來處理：它可以修改或接著寫它提出但你尚未採納的文字——寫作模式下也可以——修改會併入那個建議，而不是變成一處無法放置的編輯。對尚未決定的改寫中仍保留的文字進行編輯，也會併入該改寫，而不是在其上再疊一個建議。
- 你尚未採納的圖片，在隨後改寫文字時會和所在段落待在一起：Textus AI 會把它帶進新文字；如果改寫沒有包含它，它會留在原位置、段落之後——而不是失去位置並消失。
- 全文改寫在每處修改旁邊的頁邊都有一張卡片，而不是在頂部為全文只放一張：適用於文件中有改寫未動的表格或程式碼塊，以及多個段落的改動句子連在一起的情況。
- 修復了游標位於頁邊檢視中修訂旁邊時可能出現的錯誤。
- 以任意順序寫出的 `[text](url)` 都會變成連結：無論是把 URL 貼上到括號之間，還是先輸入 `[]()` 再填寫——游標離開後就會變成連結。你轉義過的方括號保持為文字。
- 貼上連結後輸入的文字不再併入連結。
- 輸入網址（`https://…`、`www.…`）後按空格或回車，它會立即變成連結，與重新開啟檔案後的效果一致。
- ChatGPT 和其他 OpenAI 模型聯網搜尋後寫在文字中的引用標記（`citeturn3view0` 之類）不再進入你的文件。
- Textus AI 在段落之後寫的文字，在寫作過程中和你採納之前，就會以最終的段落、列表、表格和腳註形式顯示，而不是顯示帶換行的 Markdown 原始碼。

- 頁邊的每張修訂卡片現在從一開始就有連到對應段落的線：以前被上方卡片擠下去的卡片只有在指向時才顯示連線，看起來不屬於任何內容。這些連線在指向之前顏色較淡。
- 對話卡片和頁邊中的圖片保持原有比例：以前它們被擠窄，框的形狀固定，圖片隨後又跳出框外。
- 來自相容 OpenAI 的服務、每次回覆都用相同方式給工具呼叫編號（Ollama 和 LM Studio 等本地伺服器就是如此）或根本不傳送 id 的建議，不再消失：以前第二個請求的建議會頂替第一個，結果兩個都沒了，沒有 id 的呼叫則被丟棄。
- Textus AI 重做的圖片生成後，現在會替換正文中的舊圖。以前它顯示在卡片上，但文件裡仍是舊圖，卡片也一直顯示“正在寫…”。
- 使用 Claude 時，修訂邊寫邊出現在文件中，而不是一次出現一段。
- 只合並段落、每句都保持原樣的改寫，以前看不出任何修改，採納時卻會合並段落。
- 即使 Textus AI 先寫出要改的文字、再指明所在段落，編輯也會在流式輸出時顯示；以前要等整個編輯寫完。
- 當一個請求生成的圖片數達到設定允許的上限，或沒有設定圖片模型時，AI 面板現在會用你的介面語言說明，並指出要修改的設定，而不是顯示寫給模型看的訊息。
- 回覆還在輸出時可以滾動 AI 面板：它不再隨每段新文字把你拉回底部。滾回底部或傳送訊息後，它會重新跟隨回覆。
- AI 面板輸入框中預測的下一句現在明顯比你輸入的文字更淡，不會再被誤認為是你寫的。
- AI 載入技能或使用工具後再次思考時，AI 面板末尾現在會顯示它仍在工作。以前唯一的跡象是上方的“思考中”一行，面板看起來像卡住了。
- AI 面板中較長的步驟結果（如技能的完整內容）現在在一個可滾動的獨立框中展開，收起它的那一行就在手邊，而不是遠在幾屏之外。
- AI 提出編輯時，AI 面板的變化更平穩：末尾那一行在兩次編輯之間一直顯示正在寫修改，而不是閃回“思考中”；卡片變大或變小時，下方內容平滑移動而不是跳動。
- AI 在你尚未採納的文字上方新增的標題，現在保持為獨立的標題。以前 AI 被告知標題和第一段連在一起，可能誤導它的下一步。

### 平台說明

- **macOS：** 背景模式會在選單欄新增一個 Textus 圖示，以選單欄自身的顏色繪製；點選即可開啟其選單。(#244)
- **Windows：** 背景模式下，點選通知區域中的圖示會開啟 Textus，右鍵則開啟其選單。更新程式和手動執行的安裝程式會在安裝前關閉在背景執行的 Textus。(#244)
- **Windows：** Textus 支援 105 版（2022 年）及以上的 WebView2，因此 WebView2 不會更新的電腦（如學校機房）也能獲得完整的介面。(#260)
- **Linux：** 托盤圖示需要 libayatana-appindicator，`.deb` 現在會安裝它，AppImage 也已內建；缺少它時 Textus 仍會在背景執行，設定中會說明無法顯示圖示。GNOME 需要安裝 AppIndicator 擴充套件才能顯示托盤圖示。`.deb` 和 `.rpm` 現在會在 `apt show` 和 `rpm -qi` 中顯示 Textus 的說明，`.rpm` 也註明了 MIT 許可證。(#244, #239)
- **iPhone 和 iPad：** 背景模式、開啟資料夾和檔名搜尋僅限桌面端；側邊欄照常使用。
- 來自 fork、修改 CI 或測試配置的 pull request 現在會在 `ci-config` 檢查中失敗，並請維護者稽核，因為 CONTRIBUTING.md 早已要求貢獻者不要改動這些內容。
- 為外掛打下基礎：帶自己快捷鍵的命令、編輯器右鍵選單項、側邊欄標籤頁和設定頁面，現在各透過一個登錄檔新增，詳見 docs/dev/plugin-api.md。介面上沒有任何變化。
- 從 1.2.0 起，已釋出版本有自己獨立的分支線：修復以 1.2.x 釋出，1.3.0 在 `main` 上開發；貢獻者文件說明了 pull request 應該提交到哪裡。
- 唯讀取 Textus 1.1 及之後版本儲存的資料。隨之移除的有：
  - 首次啟動時或在 **設定 › 關於** 中匯入 Levis 安裝的提示。
  - 專案 `.levis/` 資料夾的轉換，以及記憶頁中的 **轉換 Levis 資料**。
  - 從舊的 `agent/` 配置資料夾讀取寫作要求、技能和記憶。它們仍保留在磁碟上，移入 `textus/` 即可恢復。
  - 從 1.0 的單個 `chat-history.json` 讀取對話歷史，以及從 `api_key.json` 讀取 OpenAI Key。請重新輸入 Key。
- 舊版本儲存的、Textus 已不再識別的設定，現在會取預設值，而不再轉換：
  - Agent 模式的提問、編輯或計劃變為審閱。
  - 不再對映舊的服務商名稱。
  - `${filename}.assets` 這樣的圖片資料夾變為 `assets/`。
  - 在舊版指南中進行到一半的引導會重新開始。
