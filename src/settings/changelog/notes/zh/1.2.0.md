## 更新内容

Textus 1.2.0 让 Textus AI 能做的更多，编辑器也更好用。Textus AI 可以在所有服务商下联网搜索并注明出处，一键深度思考，边写边配图，读取文件夹里的长文件、PDF、Word、幻灯片、表格和图片，调用 MCP 服务器提供的工具，从你拒绝的修改中学习，也能一键彻底关闭；它的修订边写边出现在文档里，落在它要改的那一段，你自己改动后也不会失效，页边再拥挤，卡片也始终在对应文字旁边。服务商新增豆包和 MiniMax。编辑器可以打开整个文件夹，只保存你改过的部分，支持 wikilink 和指向标题的链接，能把 Word 文档作为 Markdown 打开，在原处展开链接供编辑，自动补全括号和引号，超长文档也依然流畅。设置新增搜索框；Textus 支持屏幕阅读器、纯键盘操作和高对比度，也能在较旧的 Windows 电脑上运行。

### 新增

- 打开 **设置 › 通用 › 应用 › 在后台保持运行**（默认关闭）后，关闭最后一个窗口时 Textus 仍保持运行，并在通知区域、系统托盘或菜单栏显示图标。图标菜单里有 **打开 Textus**（恢复你之前打开的文档）和 **退出 Textus**；关闭该设置后图标立即消失。没有窗口打开时，Textus 不保留任何已加载的页面，也不在后台运行任何任务。(#244)
- 用 **文件 › 打开文件夹…** 在侧边栏打开整个文件夹：在其中打开文档时，文件树保持以它为根；文件夹会随会话恢复，也会出现在 **文件 › 最近打开** 中；**文件 › 关闭文件夹** 让文件树恢复跟随当前文档。(#152, #79)
- 打开 Word 文档（`.docx`）——无论是在 **文件 › 打开…** 中选择、拖到窗口上，还是由文件管理器交给 Textus——都会生成一个同名、尚未保存的 Markdown 新文档：标题、带编号的列表、表格、粗体、斜体、链接、脚注和图片都会带过来，而只是看起来像 Markdown 的文字（如 `*`、`#` 或 `$5`）仍保留为文字。一条不打扰的提示会说明部分格式可能有差异。第一次 **保存** 时会建议在 Word 文件旁边存为 `.md` 文件，并像粘贴的图片一样，把图片移入 **设置 › 图片** 指定的图片文件夹；Word 文件本身不会被改动。(#296)
- 在侧边栏 **文件树** 标签顶部的搜索框里搜索已打开文件夹中的文件名——先列文档，再列其他文件，也可以用搜索框旁的筛选只看文档——跳过 `.gitignore` 排除的内容和 `node_modules` 等文件夹：输入即筛选，`↑`/`↓` 移动，`Enter` 打开，`Esc` 清空；`Ctrl/⌘ + Shift + O` 可直接跳到这里（可在 **设置 › 快捷键** 中修改）。(#196)
- 支持 Obsidian 的 wikilink——`[[Note]]`、`[[Note|text]]` 和 `[[Note#Heading]]`——作为链接：`Ctrl/⌘ + 点击` 会从同一文件夹或整个 vault 中打开对应笔记（若指定了标题，则跳到该标题）；保存时它们和行首的 `#tags` 一样按原样写入，不再变成 `\[\[Note]]` 和 `\#tag`。(#234)
- `Ctrl/⌘ + 点击` 指向其他文件中某个标题的链接（如 `[see](./notes.md#heading)`）时，会在新标签页、或该文件已打开的标签页中直接跳到那个标题，而不是文件开头。(#233)
- Textus 恢复上次会话，或你从 **文件 › 最近打开** 中选择文档时，只要文件之后没有改动，光标会回到你上次离开的位置，并滚动到那里；关闭 **设置 › 通用 › 启动时恢复上次会话** 时，文档仍像以前一样从开头打开。(#218)
- 新增 **下一个标签页** 和 **上一个标签页** 快捷键：所有平台上为 `Ctrl + Tab` 和 `Ctrl + Shift + Tab`（Mac 上另有 `⌘ + Shift + ]` / `⌘ + Shift + [`）；新增 **标题 1** 到 **标题 6** 的快捷键，与 Typora 一样为 `Ctrl/⌘ + 1` 到 `6`，并显示在 **格式** 菜单中对应项旁边；还有 **正文** 的快捷键，默认未绑定。这些都可以在 **设置 › 快捷键** 中修改，**还原** 可把改过的恢复原样；该页现在也列出无法修改的快捷键，如保存、缩放、粗体和斜体。如果某个操作已经占用了这些按键，它会保留原按键，相应的标题级别则默认不绑定。(#214)
- 新增 **设置 › 编辑与外观 › 界面文字大小**——90%、100%、110% 或 125%——可放大或缩小侧边栏、大纲、标签页、AI 面板及其独立窗口、菜单和设置中的文字，文档本身的缩放保持不变。(#150)
- 代码块的语言选择器旁新增 **复制** 按钮，可复制整块代码；代码块还可以显示行号，在 **设置 › 编辑与外观 › 代码块显示行号** 中开启。开启后长行改为横向滚动而不再折行，让每个行号始终对齐它的那一行。按钮和行号都不会出现在 PDF、导出文件或打印稿中。(#233)
- 按 **设置 › 编辑与外观 › 颜色代码前的色块**（默认关闭）的设置，在颜色代码前显示一个小色块：**仅在代码中** 会在表示颜色的行内代码（如 `#0af` 或 `rgb(0 128 255)`）和代码块里的颜色字面量前显示；**全文** 还会在段落、标题、列表、引用或表格正文中任意位置的六位或八位十六进制颜色值和颜色函数前显示，如 `#ff8800`、`hsl(120 50% 50%)` 或 `oklch(70% 0.1 150)`。正文中的短代码、`#cafe` 这样的标签、`#234` 这样的 issue 编号、`red` 这样的颜色名以及链接保持原样；色块不属于文字，因此不会被保存、复制或打印，也不会进入导出文件。(#146)
- 新增 **设置 › 编辑与外观 › 图表引擎**：默认仍是 Mermaid，也可以选择 [Pele](https://pele.run)。Pele 绘制同样的 ` ```mermaid ` 代码块，速度更快、下载体积小得多，切换外观或主题时无需重绘，但它有自己的排版方式，也缺少少数功能，例如标签中的 HTML。Pele 画不了的图表会交给 Mermaid 绘制；编辑器、分栏视图和所有导出都使用你选择的引擎。(#242)
- 新增 **深度思考** 按钮，即 AI 面板及其独立窗口中联网搜索旁边的灯泡，让模型在回答前先把请求想透——更慢、花费也更多，适合难题和长篇改写。它会一直保持开启，跨对话、跨文档都有效，直到你再次点击；只有支持深度思考的模型才会显示。快速提问则会要求模型快速作答。
- 模型思考时，回复上方显示“思考中 · 8 秒”，结束后显示“思考了 12 秒”；这一行默认收起，点击即可展开查看推理过程（包括 Gemini），前提是服务商提供推理内容。推理过程不会随对话保存。每个模型支持哪些思考参数现在取自 [models.dev](https://models.dev)；服务商拒绝这些参数时，会去掉它们重新发送请求。
- Textus AI 可以读取项目文件夹中的 PDF、Word、PowerPoint 和表格文件并搜索其中的文字；使用能识别图片的服务商时，还能查看其中的 PNG、JPEG、GIF 和 WebP 图片，每张最大 6 MB。(#261)
- **设置 › Textus AI** 的服务商中新增 **豆包（火山引擎）**（英文界面为 Doubao (Volcengine)），由火山方舟提供：对话使用 Doubao Seed 2.1 Pro，可以读取附带的图片并编辑文档；补全和语法检查使用关闭思考的 Seed 2.1 Turbo。请在火山方舟控制台创建 API Key 并开通这些模型。(#263)
- 服务商中新增 **MiniMax**，分为 **MiniMax（国内版）** 和 **MiniMax（国际版）**，因为两个平台只接受各自的 Key：对话和编辑使用 MiniMax-M3，补全和语法检查使用 M3.1 Flash，生成图片使用 image-01，共用同一个 Key。
- 从你的修订选择中学习：当你在多次建议中反复拒绝同一类修改——把「」改成“”、把一个词换成另一个、拆分句子、加上牛津逗号——审阅结束后，Textus AI 会提议把它记为一条写作要求，并提供 **记住**、**暂不** 和 **不再询问**。选择记住后，它会保存在记忆页的 **AI 记住的** 下，你可以删除；Textus AI 每天最多询问一次，不经你点击不会保存任何内容。只会在这台电脑上记录你采纳或拒绝的修改类型，且从不发送出去。
- 在 **设置 › Textus AI** 中选择 **图片模型** 后，Textus AI 就能为文档配图——支持 OpenAI、Google Gemini、豆包（火山引擎）、阿里通义千问、智谱 GLM、硅基流动或兼容 OpenAI 的接口；默认为 **无**，对话已在使用的服务无需再填一个 Key。在写作或修订模式中提出要求，或右键段落选择 **为这段配图**：图片会作为建议出现在原处，只有采纳后才会按 **设置 › 图片** 的设置保存到图片文件夹或上传到图床，拒绝则不留任何痕迹；服务拒绝某个描述时，AI 面板会显示原因。(#194，部分想法来自 #221)
- 所有 AI 服务商都能联网搜索：能自行搜索的模型（OpenAI、Claude、Grok、OpenRouter、Groq、通义千问、智谱 GLM）使用自带的搜索；其余的——DeepSeek、Gemini、Mistral、Kimi、本地模型和自定义接口——由 Textus 通过 **设置 › Textus AI › Textus AI 对话 › 联网搜索** 下的 **搜索服务** 来搜索：**自动** 会使用你已有的 DeepSeek、智谱或 Kimi Key，也可以选择 Bocha、Tavily、Brave Search 或 Exa 并填写各自的 Key，或使用你自己的 SearXNG 服务器。你给出网页或 PDF 的地址时，Textus AI 也能读取——仅限公网，绝不会访问你的电脑或局域网；没有可用的搜索方式时，联网搜索按钮上会显示红点。(#278)
- 回复引用的网页会列在回复下方，所有服务商、整段对话都统一按 [1]、[2] 编号；点击即可在浏览器中打开。用到网络资料的建议，其卡片上有 **把来源加为脚注**，采纳时会把来源作为 Markdown 脚注添加到文档末尾。(#278)
- 设置的分类上方新增搜索框：输入一个词，所有页面中匹配的设置项会按页面列出——包括名称、分组标题、更多主题和关于 Textus、快捷键列表，以及 **?** 背后的说明——不区分大小写、重音和全角字母。`↑`/`↓` 移动，`Enter` 或点击会打开该设置所在页面并短暂突出显示它，`Esc` 清空；设置打开时按 `Ctrl/⌘ + F` 可跳到搜索框。
- 用窗口栏最右侧的按钮可以彻底关闭 Textus AI，按钮图标由机器人改为应用图标中羽毛笔的剪影：右键可暂停 Textus AI 一小时或将其关闭；关闭期间羽毛笔上会显示一道斜线，点击可选择重新开启；暂停会自动结束。**设置 › Textus AI › 开启 Textus AI**（默认开启）、可在 **设置 › 快捷键** 中设置的快捷键，以及 iPhone 上的菜单也都能开关它。关闭期间，从 Textus 启动那一刻起，不会向任何 AI 服务发送任何内容：没有补全、语法检查、对话或记忆；AI 面板、快速提问和右键菜单中的 AI 项都会隐藏，正在生成的回复也会停止。已经提出的修改仍可采纳或拒绝；各项功能保留各自的设置，待 Textus AI 重新开启时沿用。(#196)
- 括号和引号自动补全，与 Typora 一致：输入 `(`、`[`、`{`、引号，或用中文、日文输入法输入 `（`、`【`、`「`、`“` 时，会在光标后补上对应的闭合符号。再输入闭合符号会直接跳过它，紧接着开符号按 Backspace 会将两者一起删除；选中文字时则把这对符号包在文字两侧。在代码、公式或网址中、单词前，以及作为撇号使用时（如 "don't"）不会补全。可在 **设置 › 编辑与外观 › 补全 ()、[] 和 “”** 中关闭。
- 光标位于链接上时显示其 Markdown 源码，与 Typora 一致：点击链接，或用方向键移到链接上，`[text](url)`——或 `[text](url "title")`、`[text][ref]`、`<https://…>`、裸网址——就会展开，文字和地址都可以编辑；光标移开后它又变回链接，并带上你的修改，如果已不再是链接则变为普通文字。`Ctrl/⌘ + 点击` 仍可打开链接；只是看了看的链接会原样保存，改过的则按你输入的内容保存。
- 桌面端侧边栏的文件树成了一个小型文件管理器：
  - 右键文件夹、文件或下方空白处，可在该位置 **新建文档** 或 **新建文件夹**；
  - 把文件或文件夹拖到另一个文件夹上即可移动，已打开的文档会跟着移到新位置；
  - **排序** 可按名称或修改时间排列文件树。
  - 不会覆盖任何内容：已被占用的名称会被拒绝。
- 窗口栏开头新增侧边栏按钮：Mac 上紧挨红绿灯按钮，全屏时位于红绿灯所在的角落；Windows 和 Linux 上位于菜单按钮旁边。侧边栏滑入滑出时，按钮位置保持不动。
- 用 ChatGPT 订阅自带的图片额度生成图片：用 ChatGPT 登录后，**设置 › Textus AI › 图片服务** 中会出现 **OpenAI · ChatGPT 订阅（实验性）**。它使用 ChatGPT 自家应用所用的服务，而非公开 API，因此可能随时失效；OpenAI API Key 仍照常可用。
- 修改文档中已有的图片：右键图片，选择 **让 Textus AI 修改这张图…**，再说明怎么改。新图片会作为建议出现在原处；采纳后，Textus 会询问是否把旧文件移到废纸篓，除非你同意，否则保留旧文件。
- **设置 › Textus AI** 新增 **每次最多生成几张图**：说明你要几张，Textus AI 就生成几张，但不超过这个数（默认两张）。未说明数量时生成一张，或者为较长内容中适合配图的每个部分各生成一张，并先说明配在哪里。
- **设置 › 扩展** 汇集你为 Textus 添加的内容，各占一个标签页：主题（主题库和你自己的主题）、Skill 和 MCP。每一项都是一张带开关的卡片。
- MCP 服务器能为 Textus AI 提供更多工具：文件夹、数据库、搜索，任何有 MCP 服务器的东西都可以。通过启动它的命令或它的 URL 添加，保存前可以先试用、查看它提供的工具，然后开启；Textus 会在后台启动它，Textus AI 在帮你时就可以调用这些工具，每次调用都会显示在对话中。arXiv（搜索和阅读论文）、ARES（按 DOI 查找论文及其 BibTeX）和 Context7（编程库的最新文档）可直接添加，都无需账号或 Key。命令的查找方式与终端相同，因此从程序坞启动时 npx 和 uvx 也能用。
- Textus AI 仍在回复时，你发送的消息会被保留：它们排在输入框上方，每条都有 **编辑** 和 **移除**，当前回复结束后依次发送——每条都基于当时的文档内容来处理。**停止** 会停止回复，并把排队的消息放回输入框；回复失败后，它们会等待你点 **继续**。
- 文档底部新增批注栏：可以逐条查看批注、一次性全部标为已处理，或选中几条一起询问 AI。

### 改进

- **学术润色**（`/academic`）现在也适用于基金申请书，而不只是论文：除了正式措辞、单位和引用格式，它还会删去套话式开头、夸大其词、空洞的强调词和言过其实的动词，让每个论断不超出证据所能支撑的程度，保留证据所需的限定语，对照可行性检查申请书的研究目标（NSF、NIH、国自然），并让所有数字、公式、引用和引用键保持原样。每处修改都以建议的形式给出，回复中附一份简短的修改说明；它改进的是写作本身，而不是用来规避 AI 使用声明的工具。改编自 [academic-humanizer](https://github.com/AIScientists-Dev/academic-humanizer)（MIT），后者基于 [humanizer](https://github.com/blader/humanizer)。
- 只保存你编辑过的块：其他段落、标题、列表和表格都按文件中原来的样子写回，因此同时用 Git 管理或在其他应用中编辑的文件，只会出现很小的 diff，而不会被整体重新格式化。(#234)
- Textus AI 还在写修订稿时就逐句显示改写：每句写好就出现在原处，被替换的原句以删除线显示在旁边，保留不变的句子原样不动；不再是整段划掉、新文字跟在后面流式输出、直到最后才逐句排开。写完时不会有任何跳动；**停止** 会保留已写完的句子，段落其余部分维持原样。(#243)
- 修订动画更平和、更统一：新文字、删除线和 ✓ / ✕ 以相同节奏淡入，快速相继出现而非逐个登场，没有模糊或弹跳；采纳的文字在原处从绿色渐渐褪去，而不是瞬间切换。(#243)
- Textus AI 还在写修订稿时就开始统计并显示修改：审阅条从一开始就在，计数随修改逐处增加；每处修改一写完就有了页边卡片，‹ › 和视图菜单也已可用；**采纳** 和 **拒绝** 要等改写全部完成，或你按下 **停止** 之后才能使用。(#258)
- 拖动侧边栏或 AI 面板的边缘时跟手更紧，打开和关闭 AI 面板的开销也更小：两者都不再在每一步重新计算窗口中所有元素的样式。(#284)
- 页边卡片需要空间时，正文一次性平滑移开，而不是每一帧都重新排版整篇文档；卡片被挤动时平滑滑到新位置，批注的按钮直接占好位置再淡入，而不是让卡片逐帧变大；卡片只在显示内容变化时才重绘，不会因为流式改写改动了文字就重绘一次。(#284)
- 你打开的文件夹会作为 Textus AI 的项目文件夹，除非你已经为 AI 单独选过一个。(#152)
- 记忆与对话分开进行：每次回复后，同一个模型会再简短地回顾一遍这轮对话，添加、更新或忘记 Textus AI 记住的内容——人物的变化会写进其资料库条目，而不是新建一条；你收回的偏好会被忘掉，回复下方提供 **撤销**。一次回复引起的变化以一个列表显示在回复下方，回复本身也不再花一个步骤去记忆。
- 所有项目的记忆都保存在 Textus 设置文件夹下名为 `textus` 的文件夹中，结构与项目的 `.textus/` 相同；早期版本的 `agent` 文件夹会在首次运行时重命名。
- 记忆页内容较多时可以搜索；每组记忆可以在其所在文件夹中显示；Textus AI 记下过一次的人物、地点和术语会出现在资料库中，标为 **AI 记下的**。
- 翻译或改写整篇文档时，生成一个整体建议，边写边出现在原处，而不是每次五段：一篇 1,000 字配一张图的故事，用 ChatGPT 现在约需 40 秒，以前要 80 秒。服务商一次性发来的文字（如 MiniMax 的编辑）仍会以均匀的速度逐字出现。
- 长请求用完步数时，会用你的界面语言说明，并提供 **继续**，从中断处接着做。
- 使用 Gemini、Seedream 和 ChatGPT 订阅重做图片时，以原图为基础：旧图片会和修改描述一起发送，其余部分保持不变。
- 每次回复后，在空的输入框里以灰色预测你接下来可能要说的话；按 **Tab** 采用，输入其他内容则放弃。这会多发一次简短请求；可在 **设置 › Textus AI › 预测下一句** 中关闭。
- 某张图片没有生成成功时，可以点它框里的 **重试** 单独重新生成，其他图片保持不变。
- 你在记忆页删除的内容，或 Textus AI 忘记的内容，会在 **最近忘记的** 中保留一段时间，可以 **恢复**。
- 记忆多到放不下时，会选取与你当前请求相关的记忆，而不是只取最新的；人物的变化会从它开始的地方记起（“从第 4 章起……”），不会丢掉之前的设定。
- 交给 Textus AI 的 Word、PowerPoint 或表格文件（无论是附件还是在项目文件夹中）会保留结构——标题、编号和项目符号列表、表格、粗体、斜体、链接和脚注，每张幻灯片一节并附演讲者备注，表格中的日期按日期处理——而不是纯文本；项目文件夹中的 EPUB 电子书和 RTF 文件也能读取，HTML 文件可作为附件。(#271)

- 侧边栏会打开你上次停留的标签页——文件树、大纲或剪贴板——不再每次启动或打开新窗口都回到文件树。(#196)
- 长文档依然流畅：输入、回车以及 Textus AI 读取文档时，不再每次都遍历整篇文档；远离屏幕的公式、图表和图片在你滚动接近时才绘制；自动补全、语法检查和实时图表在约一百五十万字符以内的文档中保持开启，而不是超过十万字符就关闭。在 5,000 段的文档中，回车从半秒多降到几十毫秒，打开时间缩短约一半。(#274, #277, #283, #285, #295, #307, #309)
- 用下划线输入的 `_italic_` 会变成斜体并保存为 `_italic_`，而不是保持为文字并保存为 `\_italic\_`；`snake_case` 等单词内部的下划线保持原样。
- 在表格中按 Tab 和 Shift+Tab，光标会移到下一个或上一个单元格文字的末尾，而不是选中整个单元格（之前下一个按键会把内容替换掉）。
- 在表格单元格中按 Shift+Enter 会在单元格内换行，保存为 `<br>`，重新打开文件时仍显示为换行。以前它没有任何作用。

- 文件树上方显示父文件夹的名称，如“‹ Documents / notes”，一键即可回到上一级，取代了以前容易被误读为“折叠”的箭头。
- 搜索框旁的筛选（**所有文件** 或 **仅文档**）现在也作用于文件树。以前它只影响搜索结果，因此不搜索时两个选项看起来没有区别。
- 未保存文档的空文件树标签中不再显示“打开文件夹”按钮；**文件 › 打开文件夹…** 和文件树工具栏中的按钮仍然保留。
- 两个输入时自动补全成对符号的设置，按补全的对象命名：**补全 \*\* 和 \`** 和 **补全 ()、[] 和 “”**。
- **视图** 菜单中不再包含 Textus AI；可以用窗口栏中的按钮、**设置 › Textus AI** 和可自定义的快捷键开关它，iPhone 的菜单中仍保留。
- 窗口中的所有颜色现在都来自导入的 Typora 主题可以覆盖的变量：查找栏的匹配项、页边卡片、审阅条、开关和阴影以前都是固定的。删除按钮的红色和警告色现在也像其他颜色一样跟随主题的页面。
- 主题可以在 `:root` 上设置窗口自身的颜色（`--sidebar-bg`、`--chrome-accent` 等，见设计指南），优先于 Textus 根据页面推算出的颜色。

- 粘贴的 API Key 显示为前六位和后四位字符，中间用 `***` 隔开，如 `sk-pro***wxyz`，而不是与 Key 等长的一串圆点，也不再提示保存为密码。保存的仍是完整的 Key。
- 图片默认跟随对话服务商：用 ChatGPT 登录时用 ChatGPT 的图片；其他能生成图片的服务商用自己的图片服务，共用同一个 Key；不能生成图片的服务商则不提供配图。服务和模型现在分成两个选项，而不是把所有服务的所有模型放在一个列表里。
- 边写边配图，空白页面也可以：Textus AI 把每张图片写在正文中该在的位置，写到那里时图片就开始生成，文字继续往下写；图片到来之前，它的框以对应形状占位，并有轻柔的动态效果。文字和图片是同一个建议；**采纳** 会显示“图片生成中…”并等图片全部到齐；服务拒绝生成的图片会在原处说明原因，采纳文字时不包含它。
- 保留你还没决定的内容：在尚未采纳的段落之后要求配图，图片会加入那个建议，而不是替换该段落；新的请求只有针对同一位置时，才会替换之前的建议。
- 指定长度（“大约 1200 字”）时更快开始写：文字直接写进文档，回复中说明最终写了多长，而不是让 Textus AI 先在后台起草一遍来计数。

- 正在重做的图片在新图片到来之前保持原样并变暗；新图片到了之后，才把两张一起显示出来供你选择。
- 选中内容是图片时显示“已选中图片”，而不是统计其描述的字数，并把图片本身交给能识别图片的模型。
- 技能改为可选：新安装默认开启五个——校对、精简、扩写、总结和翻译——其他技能可在 **设置 › 扩展 › Skill** 中添加。如果你以前用过 Textus，原有的技能全部保持开启。你自己的技能、**自定义…** 和 **还原** 也在那里；**设置 › Textus AI** 中有指向它们的入口。
- 补全建议更短、更准：只给出你接下来肯定会写的几个词，最多到分句结束，在你输入一个词后停顿时给出——在文档中间也会，并能与光标后的文字衔接。紧跟句号或逗号之后，以及在空段落中，它会等你先写；“续写”仍会主动请求。发出的请求更少（停顿 0.8 秒、发送的文字更少），补全的花费也更低。
- Textus 启动更轻快：窗口显示前加载的内容减半（1.3 MB，以前是 2.5 MB）。其他语言、帮助指南、设置、独立对话窗口以及图表和公式引擎，都在第一次需要时才加载——设置会在窗口空闲时于后台预先加载，所以依然能立即打开——遵循与插件相同的规则。Mermaid 不再附带第二份 KaTeX。
- Textus AI 的修订立即出现：它直接指明要改哪一段，而不是先把原文抄一遍，所以回复一写出来，改写就开始出现在文档里——用 ChatGPT 订阅改写整篇文档，原先要空等约 10 秒，现在只需五分之一秒。花费也更少，因为不再回传抄写的段落；长文档受益最多：从长文档中读取的章节也以同样方式修改。每个改动的段落仍有自己的卡片。
- Textus AI 还在描述图片时，图片的框就以对应形状出现在原处，而不是等整段描述写完；重做图片会直接从旧图开始。
- 当其他地方都没有动静时，回复下方会有一行显示 Textus AI 正在做什么——“正在写修改…”“正在生成图片…”或“思考中…”——长时间的编辑或配图不再看起来像卡住了。
- 被后续请求在同一位置替换的建议，其卡片现在显示“已替换为新的建议”，而不是“已拒绝”；Textus AI 也会得知它是被替换而非被拒绝——以前它会把那个版本当作作者不想要的。
- Textus AI 改写段落时，它正在写的那一句会被着色，着色随写作推进。以前保持不变的句子没有任何提示，轻度润色可能静止好几秒，然后突然冒出一句。
- 对改写的决定粒度现在取决于它改了什么。只改了一两句：像以前一样逐句决定。整段重写：作为一处修改，旧段落划掉、新段落跟在后面，而不是一堆红绿碎片。合并或拆分段落：每个新段落一处修改，与它来源的段落对照显示。以前“把这些合并成更少的段落”会变成一处涵盖全部内容的修改。
- 页边卡片的 ✓ 改为“采纳这处修改”，因为一处修改现在可能是整个段落。
- 审阅批注随 Textus AI 写出而逐条出现在页边，回复下方显示“正在写批注…”，而不是全部写完后一次出现。批注和图片现在指明所在段落而不是引用原文，花费更少，每次都能找到对应位置；设定了宽度的图片也可以重做。
- 编辑 Textus AI 建议修改的文字时，不再丢弃该建议。只要某处修改所改写的句子保持原样，它就仍然有效；你改过句子的那处修改会被搁置（改回去又会恢复），采纳时只写入这些修改，你的编辑保持不变。修订还在流式输出时也是如此。
- Textus AI 的编辑会落在它要改的地方：它看到的文档与编辑器中的一致，按段落划分——列表或引用是一块，表格是一块，图片是一块——每处编辑都指明要改哪一块，因此会放在那里，而不会落到文档其他地方相同文字的副本上。段落内改动的几个词只在该段落内查找。
- 对 Textus AI 改写中的图片、表格、代码块或公式，按编辑器的方式加以区分，因此每个都作为一处修改来决定，改写中与文档中保持一致。
- 批注和修订卡片较多时，仍会留在相关文字旁边。拥挤段落的卡片会裁剪到与其所在行等高的空间，小改动只显示变化的词，批注多于行数时合并为一个“8 条批注”标签。点击任意一个即可查看完整内容。
- 点击页边的批注或修订卡片，或用底部的栏跳到某一条时，卡片和相关文字会一起高亮，文字以一次平滑滚动进入视野，无论有多远。一组批注只画一条连线。
- AI 连续提出几处编辑时，AI 面板把它们显示为一张卡片，而不是一列卡片：每处编辑一行，各有采纳和拒绝；理由相同时只写一次；另有“全部采纳”/“全部拒绝”。较长的列表只显示前几行，其余收在“展开其余 N 处”后面；所有编辑都决定后，卡片折叠成一行状态。

### 修复

- 保存在隐藏文件夹（如 `~/.notes`）中的文档，其图片现在可以正常显示，以前会显示为“Textus 无法显示的格式”。
- ChatGPT 生成的图片按要求的比例绘制：以前要正方形却得到宽图。
- 翻译后的标题在等待审阅时，新文字不再带有 Markdown 的 `#`；审阅批注中的 **粗体** 术语显示为粗体，而不是夹在星号之间。
- 联网搜索较久的 Claude 回复能完整结束，不再中途截断；带引用的回复也不再在每处引用处断成短行。(#278)
- 行内补全使用光标周围正文的语言，正文太少无法判断时使用界面语言，不再在图表或代码块之后偶尔换成另一种语言；光标附近只有图表时，输入过程中不再给出建议。(#256)
- 你输入其他内容、开始用输入法输入，或 Textus AI 显示建议时，补全会立即消失；你输入的正是补全的开头时，补全则相应缩短；你已经继续往下写之后才到达的补全不再显示。(#256)
- 保留引用式链接 `[text][ref]` 及其 `[ref]: url` 定义，以前编辑后第一次保存会把它们变成行内链接并删除定义。(#234)
- 以 `---` 分隔线开头的文件中，列表和引用会被识别为列表和引用，而不是纯文本（以前编辑后会带着转义符保存）。(#245)
- 编辑段落时保留链接文字中的方括号，如 `[Tech [Episodes]](…)`，不再保存成读回来会变成公式的形式。(#245)
- 编辑段落或把其中某个词设为粗体时，包住粗体或斜体文字的链接保持为一个链接，不再被保存成三个链接。(#245)
- 删除或设置其中文字的格式后，粗体和斜体文字按显示的样子保存：删除最后一个词不再在文件中留下多余的 `**` 或 `*`；紧挨粗体文字设为粗体的词，或并排的两个代码片段或公式，不再连在一起。(#245)
- 以 `# `、`- ` 或 `1. ` 开头的一行文字，在其后的词被删除或设为粗体后，仍保存为文字，而不是标题或列表项。(#245)
- 删除某行唯一的词或某行以 `<br>` 结尾时，段落保持完整；段落末尾的换行不再被保存为多余的反斜杠。(#245)
- 在文档其他位置编辑时，文件中的 `<br>` 标签保持你写的原样。(#245)
- 删除列表项的第一行时，其余内容仍留在该项中；列表项中的分隔线保持为分隔线；`## Item #` 这类标题结尾的 `#` 得以保留。(#245)
- 从子文件夹中打开文档时，文件树保持原位，已展开的文件夹仍然展开——以前会跳进那个子文件夹。(#152)
- 跨多行的建议只给文字着色，不再给其中的换行着色：硬换行和两段之间的空行不再在行尾或空行上出现一小截绿色，指针悬停时也不会；硬换行之后的改写不再多划掉一个字符，也不再显示为一整块。(#243)
- 在 **修改在正文，原文在页边** 和 **只看结果，不加标记** 模式下，改写把多段合并为一段时，正文中不再留下空白；被挤到远离对应段落的页边卡片，其连线不再作为杂乱的线条画在卡片旁边：这类卡片的连线在指向或跳到它时才显示。(#258)
- 两张粘贴的图片在同一时刻保存时（例如在两个窗口中），各自保存为独立的文件，后一张不再覆盖前一张。(来自 #221)
- 用 **文件 › 另存为…** 把文档存到其他文件夹时，图片会一起带过去，复制到 **设置 › 图片** 为新文件设定的图片文件夹中，新文件不再缺图；在 macOS 上，新文档中粘贴的图片在首次保存时也会移到文档旁边，而不是留在 Textus 自己的文件夹里。(来自 #221)
- HTML 导出保存到文档文件夹以外时，本地图片会嵌入页面，而不是指向不存在的文件；PDF 导出的每张图片都从其文件读取，不再有空白图片。(来自 #221)
- AI 面板独立窗口中的历史记录、新对话和置顶按钮，现在与停靠面板中的大小和粗细一致，不再被挤成细条并显得发淡。(#287)
- 遵循系统的高对比度设置：开启 **增强对比度**（macOS）或高对比度主题时，次要文字与正文一样深，Textus AI 的新文字除着色外还加下划线；在 Windows 的 **对比度主题** 下，卡片、各种栏以及选中的标签页或行会以系统颜色保留边框，不再随阴影和着色一起消失。
- 只有在系统要求减少动态效果时，审阅条的出现和消失以及指针下页边卡片的移动才改用淡入淡出，与其他界面一致。
- 在默认的浅色和深色外观中，灰色和彩色文字的对比度至少为 4.5:1（WCAG AA）：引用、代码高亮、建议修改中被划掉的原文、侧边栏中的文件夹名和搜索结果、AI 面板的标签页、建议卡片的 **已拒绝**，以及深色外观中的红色按钮。
- 首次启动时关闭窗口，无论是通过关闭按钮、`Alt + F4`、`⌘ + W` 还是窗口管理器（如 niri 的关闭窗口），未保存更改的提示现在显示在语言欢迎页前面；以前提示被画在欢迎页后面，窗口因而没有关闭，看起来像关闭操作被忽略了。
- 在 WebView2 较旧的 Windows 上（许多 Windows 10 电脑都是如此），设置和应用的其他对话框能适应较矮的窗口：标题和关闭按钮留在屏幕上，页面在内部滚动，而不是对话框超出窗口上下边缘且无法滚动。(#260)
- 粗体、斜体和删除线中的行内代码得以保留：在粗体中输入 `` `code` `` 现在会变成代码，而不是保留带反引号的文字；`Ctrl/⌘ + B` 能把含有代码的选区设为粗体；在代码两侧重新输入删掉的 `**` 能恢复粗体；以粗体、代码或公式开头的粘贴内容保留其格式，而不是变成纯文本。(#318)
- 较长的表头会像正文单元格一样折成多行，而不是保持一行把表格撑宽，或在设置了列宽时以及打印和导出中压到下一列上；负责人这类短表头保持完整。(#318)
- 输入 Markdown 的效果与其写法一致：`* ` 开始无序列表、`***` 生成分隔线，与 `- ` 和 `---` 相同；`####### ` 保持为文字；在标题中按 Shift+Enter 会换行，而不是在保存时变成下划线式标题，在代码块中则添加一行；在行内代码中按 Enter 会拆分该行；Tab 和 Shift+Tab 对代码块中选中的行缩进和取消缩进，而不是替换它们或跳出编辑器；wikilink 之后输入的文字不再并入其中；在文档开头或末尾的表格中，从任意单元格都能用方向键离开表格；粘贴到表格单元格的多行内容留在该单元格中，不再覆盖旁边的单元格。(#320)
- 在 WebView2 较旧的 Windows 上（如不更新的 Windows 10 电脑），界面完整显示：关闭状态的开关重新有了轨道，卡片、设置分组和审阅条有了背景和边框，建议的编辑有了红绿色；编辑器的右键菜单、查找栏和 **插入表格** 对话框在正确的位置打开，不再偏到一边；侧边栏可以重新调整宽度；AI 面板的空白状态不再闪烁；源码模式居中显示；带链接的 Mermaid 图表能正常绘制。(#260)
- Textus AI 获取的所有地址——从网上读取的页面，以及图片服务以链接形式留下的图片——都经过同样严格的检查，因此都无法通过换一种写法的地址访问这台电脑或你的局域网，例如携带私有 IPv4 地址的 IPv6 地址、6to4 或 NAT64 地址，或 `printer.local` 这样的名称。(#327)
- 更多 Markdown 编辑行为符合预期：`Ctrl/⌘ + B` 和 `Ctrl/⌘ + I` 又能去掉词语的粗体和斜体，在刚输入的内容末尾按下时会结束格式、后续文字恢复普通，与 Typora 一致；输入 `[text](url` 后，越过自动补上的 `)` 时它就变成链接；Tab 和 Shift+Tab 不会再把焦点移出正文；格式 › 无序列表或有序列表可以切换列表类型；在标题开头按 Backspace，无论哪一级都会变成正文，在提示框第一行按则保留提示框（再按一次变成普通引用）；`~~~` 开始代码块，第一行的 `---` 开始 front matter，`1) ` 开始列表，而 `===` 保持为文字；手动输入的 HTML、`<br>` 和脚注引用按输入的样子保存；在空格前按 Enter 不再保存出 `&#x20;`；← 和 → 一样在行内 HTML 上每次移动一个字符；粗斜体按一次方向键即可展开；删除代码外粗斜体的最后一个词不再让两种格式都丢失；编辑过的段落保留两个空格的换行，表格中的中日韩文字能对齐；Word 列表粘贴后仍是列表，在行中间粘贴的标题保留其 `#`；设置 › 快捷键会指出某个按键属于哪个固定快捷键。(#329)
- AI 面板滑入页面旁边时，窗口其他部分不再移动，无论侧边栏是否打开。以前在 Mac 上打开它会把侧边栏和正文推到一边，滑动结束时又弹回原位。在较小的窗口中，它还会带着阴影盖在页面上（与全屏时不同），之后打开侧边栏会改变它并重新播放滑入动画；现在它始终留在页面旁边，宽度保持不变。
- 在 Mac 上用触控板滑动到侧边栏尽头或越过标题栏时，窗口保持不动，不再整页弹动。文档本身在两端仍有回弹，短文档也一样。
- 禅模式只隐藏正文以外的所有内容并淡化其他段落，窗口保持原样，不再同时进入全屏。
- 设置中比按钮更宽的下拉列表（如 **图片模型** 的列表）留在窗口内，不再超出窗口右边缘。
- 在 Mac 上，**编辑 › 全选** 会选中文档或你所在的文本框，而不是在光标不在两者中时选中整个窗口及侧边栏的笔记。
- `~~` 和 `==` 在你输入闭合符号之前保持输入的样子，与 Typora 一致，而不是画出一个空的删除线或高亮，把两个波浪号显示成四个。`~~text~~` 和 `==text==` 仍会变成删除线和高亮。
- 在 Mac 上，手指在文档顶部或底部离开触控板时，文档立即回弹，而不是随滑动惯性滑行并在那里停顿片刻才松开。带惯性冲到尽头的滑动只回弹一次。
- Textus AI 建议的图片按采纳后的宽度显示在正文栏内，而不是按图片服务生成的原始尺寸显示，以前在采纳之前会远远超出页面。
- 对选区按 **⌘B** 或 **⌘I** 后文字保持选中，与 Typora 一致，因此再按另一个可得到粗斜体，再按同一个则取消，而不是选区消失、下一次按下在光标处开启空的格式。在按下前刚用键盘做出的选区按其显示的范围生效；在 Mac 上双击粗体或斜体词会选中该词，而不是什么都不选或选中旁边的词。
- Mac 窗口进入全屏后，侧边栏按钮移到红绿灯所在的角落，开始退出全屏时立即回到红绿灯旁边——以 macOS 报告的时机为准——而不是慢一拍，或在退出时根本不动，导致按钮被压在红绿灯下面。
- 拖到窗口上的文件在新标签页中打开，而不是替换你正在阅读的文档；只有空的未命名标签页会让位给它。
- 在 Windows 和 Linux 上，窗口内绘制的菜单中的 **文件 › 关闭窗口** 能关闭窗口了，以前没有任何作用。(#345)
- 在决定上一个请求之前就发送新请求时，Textus AI 会基于你看到的文档来处理：它可以修改或接着写它提出但你尚未采纳的文字——写作模式下也可以——修改会并入那个建议，而不是变成一处无法放置的编辑。对尚未决定的改写中仍保留的文字进行编辑，也会并入该改写，而不是在其上再叠一个建议。
- 你尚未采纳的图片，在随后改写文字时会和所在段落待在一起：Textus AI 会把它带进新文字；如果改写没有包含它，它会留在原位置、段落之后——而不是失去位置并消失。
- 全文改写在每处修改旁边的页边都有一张卡片，而不是在顶部为全文只放一张：适用于文档中有改写未动的表格或代码块，以及多个段落的改动句子连在一起的情况。
- 修复了光标位于页边视图中修订旁边时可能出现的错误。
- 以任意顺序写出的 `[text](url)` 都会变成链接：无论是把 URL 粘贴到括号之间，还是先输入 `[]()` 再填写——光标离开后就会变成链接。你转义过的方括号保持为文字。
- 粘贴链接后输入的文字不再并入链接。
- 输入网址（`https://…`、`www.…`）后按空格或回车，它会立即变成链接，与重新打开文件后的效果一致。
- ChatGPT 和其他 OpenAI 模型联网搜索后写在文字中的引用标记（`citeturn3view0` 之类）不再进入你的文档。
- Textus AI 在段落之后写的文字，在写作过程中和你采纳之前，就会以最终的段落、列表、表格和脚注形式显示，而不是显示带换行的 Markdown 源码。
- Textus AI 请求不再挂起：最后一个事件到达后回复即结束，即使服务仍保持连接；服务连续五分钟只发送保活信号时会报错放弃，而不是无限期等待（ChatGPT 模型曾出现这种情况）。
- 补全不再重复光标处输入了一半的中文或日文词（十分 + 分钟 变成 十分分钟）、文字末尾已有的逗号，也不再以省略号开头。
- 你顺带提到的关于作品的事实——人物、地点、术语——会被记入项目的资料库，与你明确要求时一样。
- 没有打开项目文件夹时，不再记忆某一部作品的内容（否则它会进入你写的每一篇文档）；Textus AI 会说明记住它需要一个项目文件夹。
- 资料库条目中不再包含只有一个字或两个字母的别名，它们会匹配到太多文字。
- 页边的每张修订卡片现在从一开始就有连到对应段落的线：以前被上方卡片挤下去的卡片只有在指向时才显示连线，看起来不属于任何内容。这些连线在指向之前颜色较淡。
- 对话卡片和页边中的图片保持原有比例：以前它们被挤窄，框的形状固定，图片随后又跳出框外。
- 来自兼容 OpenAI 的服务、每次回复都用相同方式给工具调用编号（Ollama 和 LM Studio 等本地服务器就是如此）或根本不发送 id 的建议，不再消失：以前第二个请求的建议会顶替第一个，结果两个都没了，没有 id 的调用则被丢弃。
- Textus AI 重做的图片生成后，现在会替换正文中的旧图。以前它显示在卡片上，但文档里仍是旧图，卡片也一直显示“正在写…”。
- 使用 Claude 时，修订边写边出现在文档中，而不是一次出现一段。
- 只合并段落、每句都保持原样的改写，以前看不出任何修改，采纳时却会合并段落。
- 即使 Textus AI 先写出要改的文字、再指明所在段落，编辑也会在流式输出时显示；以前要等整个编辑写完。
- 当一个请求生成的图片数达到设置允许的上限，或没有设置图片模型时，AI 面板现在会用你的界面语言说明，并指出要修改的设置，而不是显示写给模型看的消息。
- 回复还在输出时可以滚动 AI 面板：它不再随每段新文字把你拉回底部。滚回底部或发送消息后，它会重新跟随回复。
- AI 面板输入框中预测的下一句现在明显比你输入的文字更淡，不会再被误认为是你写的。
- AI 加载技能或使用工具后再次思考时，AI 面板末尾现在会显示它仍在工作。以前唯一的迹象是上方的“思考中”一行，面板看起来像卡住了。
- AI 面板中较长的步骤结果（如技能的完整内容）现在在一个可滚动的独立框中展开，收起它的那一行就在手边，而不是远在几屏之外。
- AI 提出编辑时，AI 面板的变化更平稳：末尾那一行在两次编辑之间一直显示正在写修改，而不是闪回“思考中”；卡片变大或变小时，下方内容平滑移动而不是跳动。
- AI 在你尚未采纳的文字上方添加的标题，现在保持为独立的标题。以前 AI 被告知标题和第一段连在一起，可能误导它的下一步。

### 平台说明

- **macOS：** 后台模式会在菜单栏添加一个 Textus 图标，以菜单栏自身的颜色绘制；点击即可打开其菜单。(#244)
- **Windows：** 后台模式下，点击通知区域中的图标会打开 Textus，右键则打开其菜单。更新程序和手动运行的安装程序会在安装前关闭在后台运行的 Textus。(#244)
- **Windows：** Textus 支持 105 版（2022 年）及以上的 WebView2，因此 WebView2 不会更新的电脑（如学校机房）也能获得完整的界面。(#260)
- **Linux：** 托盘图标需要 libayatana-appindicator，`.deb` 现在会安装它，AppImage 也已内置；缺少它时 Textus 仍会在后台运行，设置中会说明无法显示图标。GNOME 需要安装 AppIndicator 扩展才能显示托盘图标。`.deb` 和 `.rpm` 现在会在 `apt show` 和 `rpm -qi` 中显示 Textus 的说明，`.rpm` 也注明了 MIT 许可证。(#244, #239)
- **iPhone 和 iPad：** 后台模式、打开文件夹和文件名搜索仅限桌面端；侧边栏照常使用。
- 来自 fork、修改 CI 或测试配置的 pull request 现在会在 `ci-config` 检查中失败，并请维护者审核，因为 CONTRIBUTING.md 早已要求贡献者不要改动这些内容。
- 为插件打下基础：带自己快捷键的命令、编辑器右键菜单项、侧边栏标签页和设置页面，现在各通过一个注册表添加，详见 docs/dev/plugin-api.md。界面上没有任何变化。
- 从 1.2.0 起，已发布版本有自己独立的分支线：修复以 1.2.x 发布，1.3.0 在 `main` 上开发；贡献者文档说明了 pull request 应该提交到哪里。
- 只读取 Textus 1.1 及之后版本保存的数据。随之移除的有：
  - 首次启动时或在 **设置 › 关于** 中导入 Levis 安装的提示。
  - 项目 `.levis/` 文件夹的转换，以及记忆页中的 **转换 Levis 数据**。
  - 从旧的 `agent/` 配置文件夹读取写作要求、技能和记忆。它们仍保留在磁盘上，移入 `textus/` 即可恢复。
  - 从 1.0 的单个 `chat-history.json` 读取对话历史，以及从 `api_key.json` 读取 OpenAI Key。请重新输入 Key。
- 旧版本保存的、Textus 已不再识别的设置，现在会取默认值，而不再转换：
  - Agent 模式的提问、编辑或计划变为审阅。
  - 不再映射旧的服务商名称。
  - `${filename}.assets` 这样的图片文件夹变为 `assets/`。
  - 在旧版指南中进行到一半的引导会重新开始。
- 应用与其原生端互相发送的数据，其类型现在依据同一份由原生代码生成的定义进行检查，两者不会再出现不一致。
