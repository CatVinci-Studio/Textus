## 更新内容

Textus 1.3.1 让开启插件时的大文件夹和长文档依然流畅，把引导教程缩短为八步，并新支持三种 Typora 或 GitHub 中的 Markdown 写法：`[TOC]`、上下标和 `:emoji:` 短代码。

### 新增

- 单独一行的 `[TOC]` 会像 Typora 一样显示由文档标题组成的目录：它随你的写作同步更新，点击即可跳转到对应标题。输入 `[TOC]` 后按 Enter 即可插入；保存时保留原样。
- 与 Typora 和 Pandoc 一致的下标和上标：`H~2~O` 显示为 H₂O，`x^2^` 显示为 x²，输入闭合的 `~` 或 `^` 时即生效。单个波浪号只在紧跟字母或数字时才是下标；其他位置的 `~text~` 仍像 GitHub 一样显示为删除线，`~~text~~` 则始终是删除线。中间有空格的文字（如 `2^10 and 3^4`）保持原样。
- 与 GitHub 一致的 emoji 短代码（如 `:tada:` 和 `:rocket:`）会像 Typora 一样显示为对应的 emoji。文件中保留短代码，光标移到上面时会显示短代码以便编辑。代码和链接中的内容保持不变。

### 改进

- 引导教程从十七步缩短为八个简短步骤：输入 Markdown、命令面板、**设置 › 扩展** 中的插件、主题和技能、连接 AI，以及用 Textus AI 撰写和续写笔记。表格、公式、主题、审阅等内容请看 **帮助 › 视频教程**。
- 在配备 120 Hz 显示器的 Mac 上，输入和动画以显示器的全刷新率绘制，而不是约每秒 60 帧。

### 修复

- 在一百万字符及以上的文档中输入也能跟上：按键显示所需时间约减半，粘贴或修改一行所需时间大幅缩短。
- 插件在侧边栏中显示数千项的列表（如大文件夹的任务）时，不再拖慢输入和切换文档：每次只绘制一页的行，也不会在每次按键时重新绘制。
- 在包含数千篇笔记的文件夹中，跟踪链接的插件（反向链接、关系图等）读取文件夹时不再让窗口卡住数秒：每个链接都按名称查找，而不是与所有文件逐一比对。
- 列出文件夹中笔记、标签或任务的插件（页面、标签、任务、反向链接等）在 Textus 启动后才打开文件夹时也能跟上编辑，并会在切换到其他文件夹时随之更新。
- 当文档所在位置没有 Obsidian 仓库时，`[[Wikilinks]]` 和 `![[embeds]]` 可以在侧边栏打开的文件夹中的任何位置找到笔记和图片，而不只是文档旁边。
- 插件在打开的文件夹中添加、移动或删除的文件会立即显示在侧边栏中，无需点击刷新。
- 插件的设置页面在 **设置 › 扩展** 中完整显示，不再被截断在一个小框里。
- 多行设置（插件的设置或 MCP 服务器的环境变量）显示为圆角柔和的输入框，而不是被拉伸的胶囊形状。
- 长列表的预览卡片会把项目符号保留在卡片内，不再画到卡片下方。
- 列表项中开始的代码块（如 `2. ```）之后的所有标题都会显示在大纲中。
- 公式中矩阵的各行像 Typora 一样留有间距，分式行不再挤在一起。
- 没有英文字符串的插件，在 Textus 使用其不支持的语言时，会显示插件自身的语言（名称、命令和面板），而不是 `name` 这样的原始键名。
