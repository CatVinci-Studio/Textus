# Textus AI 功能指南

Textus 提供续写、语法检查，以及围绕文档的对话和修改。本指南介绍连接服务、使用功能，以及用项目文件夹、文风档案、资料库、写作要求和技能把 Textus AI 调成你自己的写作助手。

## 连接服务

1. 打开 **设置 > Textus AI**，在**连接**的**服务商**中选择要使用的服务。
2. 展开**登录与凭据**，按该服务支持的方式登录账户或填写 API Key。
3. 使用**自定义接口**（任何兼容 OpenAI 的服务：本地模型、中转等）时，填写接口地址、所需的密钥和模型名称，再保存配置。
4. 在**写作辅助**中选择写作模型，在 **Textus AI 对话**中选择对话模型。

登录会在浏览器中完成。是否支持图片、联网搜索和文档修改，取决于所选服务与模型。

内置的模型列表只包含各服务商的默认模型（Anthropic：对话用 Claude Sonnet 5.5，续写和语法检查用 Claude Haiku 5.5）。点**连接**里模型列表一行的 **获取模型列表**，即可载入该服务商当前的全部模型并从中选择。

使用**豆包（火山引擎）**时，在[火山方舟控制台](https://console.volcengine.com/ark/region:ark+cn-beijing/apiKey)创建 API Key，并在同一控制台的**开通管理**里开通要用的模型：未开通的模型，方舟会拒绝请求。

以下快捷键按 macOS 标注；Windows 和 Linux 将 Cmd 换成 Ctrl、Option 换成 Alt。修改过快捷键时，以 **设置 > 快捷键** 中的配置为准。

## AI 功能

### 1. 续写（补全）

输入时自动在光标处给出灰色的续写建议，按 <kbd>Tab</kbd> 采纳；按 <kbd>Cmd</kbd>+<kbd>→</kbd> 只采纳下一个词，其余部分继续保留。<kbd>Esc</kbd> 关闭建议。没有最小字数限制，文档第一句话就能触发。

用 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>Space</kbd> 或右键菜单主动请求续写时（光标需在段落末尾），会得到更长的续写，并最多给出三个候选——用 <kbd>Option</kbd>+<kbd>[</kbd> / <kbd>Option</kbd>+<kbd>]</kbd> 切换。

在 **设置 > Textus AI > 写作辅助** 里可以调整**续写语气**（跟随文档 / 正式 / 轻松 / 学术 / 简洁）。如果文档所在的项目有文风档案或资料库（见下文「让 Textus AI 懂你的写作」），续写也会遵循它们。

### 2. 语法检查

对可能有问题的文字加下划线。鼠标悬停或把光标移进去即可查看说明；点**应用**（或光标在其上时按 <kbd>Option</kbd>+<kbd>Enter</kbd>）采用修改，点**忽略**则不再提示。快捷键 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>G</kbd> 立即检查当前段落。

### 3. AI 面板

完整对话位于编辑器右侧的面板中。点窗口标题栏右端的 **Textus AI** 按钮（羽毛笔图标），或按 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>L</kbd> 打开或关闭。

- **每个文档一个对话**：每个标签页有自己的对话，切换标签页时面板也随之切换。面板顶部的**新对话**重新开始（还有未处理的修改时会先询问）。
- **模式**：输入框提供两种模式。**写作**处理文档：起草新内容（续写、新的段落或章节），也修改已有的文字（改写、翻译、删减）。选中文字时，针对它的修改会替换它，新增的内容写在它之后。**审阅**回答、讨论、留下批注，不改动文档。写作的每处修改都是建议，由你采纳或拒绝。面板的初始模式在 **设置 > Textus AI > Textus AI 对话 > 默认模式** 中设置。
- **@ 引用**：在输入框中输入 `@`，即可从项目文件夹里选一个文本文件附到消息中。
- **附加文件**：点输入框左侧的 **+** 可以附上 PDF、Word、PowerPoint、表格、EPUB 电子书、RTF 或 HTML 文件、图片或纯文本。除图片外都会在本地抽成文字再随消息发出；图片则作为真正的图像发给支持视觉的服务（不支持的会直接提示，而不是悄悄丢掉）。文件很长时只会发送一部分，附件标签上会注明「已截断」。
- **联网搜索**：输入框旁的放大镜按钮让 Textus AI 在需要时上网搜索，详见下面的 **7. 联网搜索**。
- **深度思考**：联网搜索旁边的按钮（灯泡图标）让模型先把问题想透再回答——更慢，也更费钱，适合难的问题和大段改写。按下后一直开着，换文档也不变，再按一次才关。模型思考时面板显示「思考中 · 8 秒」，结束后变成「已思考 12 秒」；服务商提供思考内容时，点一下就能展开阅读。只有能深入思考的模型才显示这个按钮；快速提问总是要求快速回答。
- **历史记录**：AI 面板顶部的「历史记录」按钮（时钟图标）按文件夹列出过去的对话，点击其中一条即可连同它的文档重新打开并继续。
- **出错时**：请求失败时，对话会先说明是哪类问题、该怎么办（检查密钥、稍后再试、换一个模型），再附上服务商的原始信息。

面板顶部的**在独立窗口中打开**会把对话移到单独的窗口，适合放在第二块屏幕上。这个窗口会跟着你走：切换标签页或窗口，它的文档、标题和选区都会跟着变；提出的修改始终落在你当时正在编辑的那个文件上。每个编辑器窗口最多只有一个独立窗口；右上角的 **📌** 可以让它一直显示在编辑器上方。

### 4. 快速提问

按 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>K</kbd>（或右键 > 询问 AI…）在当前段落下方打开一个小对话条。它嵌在文档中，会把下方内容往下推，不会遮住正文。如果打开前选中了文字，会附上选中内容。快速提问默认使用**写作**模式，因为它通常是针对某段文字发起修改（「缩短这段」）；需要时可在模式选择中一键换成审阅。

- **再按一次快捷键**：对话条已打开时按 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>K</kbd> 会把光标移到输入框；在输入框中再按一次则关闭。在对话条任意位置按 <kbd>Esc</kbd> 也会关闭，光标回到正文。还有未处理的修改时，关闭或新建对话会先询问。
- 快速提问有自己的简短对话，和面板里的对话分开，也不写入对话历史；面板开着时也能弹出。点右上角的**转到大对话**，这段对话会交给 AI 面板继续，并保存到历史。打开 **设置 > Textus AI > 高级设置 > 在独立窗口中打开完整对话** 后，则改为在独立窗口中打开。

### 5. 文档内的修改

对话不会直接改动文档。当你让支持工具调用的服务修改文档时，每处修改都以提议的形式呈现在原位：删除的文字加删除线，新增的文字以绿色显示。采纳前文档不会有任何变化，<kbd>Cmd</kbd>+<kbd>Z</kbd> 可以一步撤销已采纳的修改。

- **采纳 / 拒绝**：可以用修改旁的浮动条、面板中该提议的卡片，或键盘——<kbd>Cmd</kbd>+<kbd>Return</kbd> 采纳，光标在修改上时 <kbd>Cmd</kbd>+<kbd>Delete</kbd> 拒绝。一条回复里有多个提议时会同时预览，可用 ‹› 切换，也可以全部采纳/全部拒绝。
- **修改理由**：每张提议卡片都会说明 Textus AI 为什么这样改。
- **只采纳部分句子**：一个提议改写了多句话时，卡片上会出现「N 处句子改动 · 逐句选择」——勾选想要的句子，再点**接受所选**。
- **在光标处插入**：没有选中文字时，Textus AI 知道光标的位置，「在这里写一段过渡」会正好插在光标处。
- **批注而非修改**：请 Textus AI 审阅（「这里哪里写得弱？」）时，它会把批注钉在对应段落上，而不改动原文。每张批注卡片都有**在文档中定位**，点击会选中它所针对的段落。

### 6. 图片

Textus AI 可以为文档生成图片。**设置 > Textus AI > 图片服务** 默认跟随聊天服务：用 ChatGPT 登录时，使用订阅自带的画图额度（标为实验性，因为它不是公开的 API）；聊天服务自己能画图时，用它自己的图片模型和同一个 key。聊天服务不能画图时，要先选一个图片服务（OpenAI、Google Gemini、豆包（火山引擎）、阿里通义、智谱 GLM、硅基流动（SiliconFlow），或任何兼容 OpenAI 的接口），再选它的模型。

- 在写作模式下提出（“在第一段后面配一张港口的图”），或者右键点一段，选 **为这段配图**。
- 文字和图片一起生成：文字边写边出现，图片在它的位置先显示一个缓缓流动的框，生成好就换成图片。还没生成完也可以先采纳，图片到了就会保存。
- 采纳之前什么都不会保存；采纳后按 **设置 > 图片** 里粘贴图片的规则保存，并插入为 Markdown 图片。拒绝则什么都不留下。
- 想改一张图，右键点它，选 **让 Textus AI 修改这张图…**，再说怎么改。新图会作为提议出现在原来的位置；采纳后会问你要不要把旧图片文件移到废纸篓，你不同意就保留。
- 说要几张，Textus AI 就生成几张，但不超过 **每次最多生成几张图**（默认两张，可以改）。如果服务商拒绝了某段描述，图片的位置会显示它给出的原因。

### 7. 联网搜索

打开输入框旁的**联网搜索**按钮（或在 **设置 > Textus AI > Textus AI 对话 > 联网搜索** 中设为默认打开），请求需要最新的、或它拿不准的事实时，Textus AI 会去网上查。你贴上一个网址，它也能读那个页面。

- **谁来搜索**：能自己搜索的模型（OpenAI、Claude、Grok、OpenRouter、Groq、通义千问和智谱 GLM）用它们自带的搜索。其他模型（DeepSeek、Gemini、Mistral、Kimi、本地模型、自定义接口）由 Textus 来搜索，用的是设置里“联网搜索”下面的**搜索服务**：**自动**会用你已经为对话保存的 DeepSeek、智谱或 Kimi 的 Key；也可以选博查、Tavily、Brave Search 或 Exa 并填入它的 Key，或者选 SearXNG 并填入你自己服务器的地址。这一行会写明搜索内容发给谁。没有可用的搜索时，按钮上会出现一个红点。
- **来源**：回复用 [1]、[2] 标出所引用的内容，并在下方列出这些页面；点一下就在浏览器里打开。同一段对话里，编号始终不变。
- **把来源加为脚注**：建议里用到了网上的内容时，建议卡片上会有**把来源加为脚注**。勾选后，采纳时会在文档末尾为这些来源加上 Markdown 脚注；不勾选，文字里就不带来源。卡片会记住你上次的选择。
- **网页只供阅读，不听指挥**：网页上写的任何内容都不会成为给 Textus AI 的指令，它仍然只会提出建议。Textus 只读取公共网络上的页面，从不读取你的电脑或局域网里的内容。

## 让 Textus AI 懂你的写作

Textus AI 了解你和你的作品，靠的是几个普通的 Markdown 文件，而不是藏在某处的设置。每个文件只管一件事：

| 概念 | 是什么 | 放在哪里 |
| --- | --- | --- |
| **项目文件夹** | Textus AI 工作、可以读取的文件夹 | 文档所在的文件夹，或你另选的文件夹 |
| **文风档案** | 你是怎么写的 | `.textus/style.md` |
| **资料库** | 人物、地点、术语的设定 | `.textus/library/` |
| **写作要求** | 每次对话都要遵守的常驻要求 | `agent.md`——全局一份，每个项目也可以有一份 |
| **记忆** | Textus AI 从对话中记下的内容 | `.textus/memory/`，以及全局配置文件夹里的 `memory/` |
| **技能** | 用 `/名称` 调用的可复用指令 | `skills/`——全局一套，每个项目也可以有一套 |
| **全局配置文件夹** | 对所有文档生效的那部分 | 应用自己的设置文件夹 |

下文说的「对话」，指 AI 面板和快速提问。一个完整的项目大致是这样：

```
我的小说/                ← 项目文件夹
├── 第一章.md            ← 正在编辑的文档
├── 笔记/
│   └── 时间线.md        ← Textus AI 可以查阅的参考资料
└── .textus/              ← 项目自己的设置
    ├── style.md         ← 文风档案
    ├── agent.md         ← 本项目的写作要求
    ├── library/
    │   ├── 林晚.md       ← 每个人物、地点或术语一个条目
    │   └── 港城.md
    └── skills/
        └── polish.md    ← 一个文件一个技能
```

`.textus/` 和里面的文件，都会在你第一次从项目菜单里用到时自动创建；只有项目技能需要你手动添加。这些文件里写在 `<!-- -->` 注释中的内容是写给自己的备注，永远不会发送。

### 项目文件夹

**项目文件夹就是 Textus AI 工作的文件夹。** 默认是你正在编辑的文档所在的文件夹——或者它上方最近的、带有 `.textus/` 文件夹的那个文件夹，所以 `novel/part-1/` 里的一章属于 `novel/`：文档一保存，它所在的文件夹就成了项目文件夹。

- Textus AI 可以列出、按名称查找、阅读和搜索其中的文件，用来查找某个角色之前的戏份、某个术语，或你的笔记：不超过 16 MB 的文本文件（Markdown、纯文本等格式），长文件会分段阅读；还有 PDF、Word、PowerPoint、表格、EPUB 和 RTF 文件里的文字。所用的服务能看图片时，它还能查看其中的 PNG、JPEG、GIF 和 WebP 图片，每张不超过 6 MB。隐藏文件和文件夹、`.gitignore` 或 `.ignore` 文件排除的内容（与侧边栏的文件搜索相同）、构建与依赖目录（如 `node_modules`），以及没有文字层的扫描版 PDF 都会跳过。
- 在对话输入框中输入 `@`，可以把其中的某个文件附到消息里。
- 它的 `.textus/` 文件夹存放本项目的文风档案、资料库、写作要求和技能。

AI 面板顶部下方的项目栏显示项目文件夹的名字，点一下就是**项目菜单**。参考资料不和草稿放在一起时，用其中的**选择项目文件夹…**（也可以在 **设置 > Textus AI > 项目文件夹** 中选择）。选好的文件夹会用于所有文档——包括未保存的草稿——直到你再点**改用文档所在文件夹**。

> [!TIP]
> 草稿在 `论文/草稿/`，访谈笔记在 `论文/资料/`？把 `论文/` 选为项目文件夹，编辑 `草稿/第二章.md` 时，Textus AI 就能读到 `资料/访谈.md`。

Textus AI 读取的一切都必须在项目文件夹之内：`..`、绝对路径和指向外部的链接都会被拒绝。未保存的草稿在你没有另选文件夹时没有项目文件夹；范围太大的文件夹（主目录或整个磁盘）也会被拒绝。

### 文风档案——「学习我的文风」

**文风档案描述你怎么写**，让续写和修改读起来像你写的：语气、句子节奏、用词、标点、你从不使用的写法。在项目内的每篇文档里，Textus AI 对话时会遵循它，续写在你打字时也会遵循它。它就是 `.textus/style.md` 这个文件。

有两种方式建立，都在项目菜单里：

- **从样本学习我的文风…**——选几篇你自己写的文件（最多八篇）。Textus AI 会读完这些文字，起草一份档案：语气、句子与节奏、用词、标点与格式、结构、从不使用的写法，再摘几句原文作为例子；然后在新标签页中打开。读一遍，改掉不对的，补上没写到的——它归你所有。再次学习时，旧档案会保留为 `style.previous.md`。
- **新建文风档案**——从一份空白提纲开始，自己写。

有了档案后，文件夹名旁边会出现**文风**标签，点它即可打开。

```markdown
# 文风档案

## 句子与节奏
- 多用短句，很少超过 25 个字。
- 段落先写一个具体场景，再说观点。

## 从不
- 不用感叹号，不用「突然」。
```

写具体、可以检验的要点，比写形容词有用得多：写「多用短句，很少超过 25 个字」，而不是「简洁」。篇幅控制在一两页以内，只有前 6,000 个字符会被使用。设置里的**续写语气**也同时生效——文风档案已经写清你的笔调时，把它留在「跟随文档」即可。

### 资料库

**资料库存放需要前后一致的设定**：每个人物、地点或术语一个 Markdown 文件，放在 `.textus/library/` 里。项目菜单中的**新建资料库条目…**会先问名称，再打开新条目；**资料库**标签显示条目数量。

```markdown
---
name: 林晚
aliases: [晚晚, 林老师]
include: detected
---

女主角，32 岁，在港城一所中学教语文。
左撇子。从不提起她的哥哥。
```

条目不需要你手动附加。`include: detected`（默认值）的条目，只要它的名字或某个别名出现，就会自动交给 Textus AI：对话时看你的消息和文档，续写时看光标附近的文字。`always` 每次请求都带上，`never` 则永远不带。没被提到的条目不产生任何开销，资料库可以随项目一起慢慢长大。

### 写作要求（agent.md）

**写作要求是每次对话都会附上的常驻要求**：这个项目是什么、用哪种语言回复、某些词怎么写、Textus AI 始终要做或绝不能做的事。它们写在名为 `agent.md` 的文件里，分两级：

- **全局**，对所有文档生效：**设置 > Textus AI > 写作要求（agent.md）> 编辑 agent.md**。
- **项目**，只对一个项目里的文档生效：`.textus/agent.md`，用项目菜单中的**编辑本项目的写作要求**打开。

两者都会在新标签页中打开，开头附有一段写在注释里的简短说明。两份都存在时，Textus AI 两份都会收到——先全局，后项目——有冲突时以项目的为准。

```markdown
这是一部以 1930 年代上海为背景的悬疑小说，第一人称，叙述者是林晚。
始终用中文回复。
人物名统一写作「林晚」，不要写成「林婉」。
```

写作要求只用于对话。续写不读它，而是遵循文风档案和资料库。

### Textus AI 记住了什么

**Textus AI 会记住你的要求和你的写法**，不用你自己写文件。当你告诉它一件不只适用于这一次的事——「始终用全角标点」「不要用破折号」、一处你纠正了两次的地方——或者关于作品的事实，比如某个人物是谁，它就会记下来，并在以后的对话中遵循。每次记下时，它的回复下方都有一行说明记住了什么、记在哪里：**撤销**收回这条，**改为个人**或**改为项目**把它移过去。

- **本项目**：与这部作品有关的内容，存在 `.textus/memory/`；关于人物、地点和术语的事实会放进资料库。
- **所有项目通用**：你的一般习惯，存在全局配置文件夹里的 `memory/`。没有项目文件夹时，所有内容都存在这里。

AI 面板的**项目**标签页会在**记忆**下列出全部内容，并注明每条是何时、在哪次对话中记下的：**编辑**打开它，**删除**移除它。两者冲突时以你自己写的写作要求为准，Textus AI 也从不修改你的 `agent.md` 或文风档案。记忆太多、无法全部发送时，最早的几条会被略去，项目标签页会注明这一点。**设置 > Textus AI > 自动记住** 可以关闭这项功能。

**它也会从你的修订取舍里学习。** 当你多次拒绝同一类修改——把「」改成“”、把某个词换成另一个、拆分句子、加上牛津逗号——审阅结束后，Textus AI 会询问要不要把它记成一条要求：**记住**会把它存进**记忆**，**暂不**等以后再说，**不再询问**则不再问这一类。它每天最多问一次，而且只有你点击才会保存，关闭“自动记住”时也是这样。它统计的只是你接受或拒绝了哪几类修改的简短记录，保存在这台电脑上、和记忆放在一起，从不发送。

### 技能（/名称）

**技能是一套有名字、可以反复使用的指令**——「润色」「列提纲」「核对引文」——保存在一个 Markdown 文件里：开头是名称和一句话描述，下面是完整的指令。

```markdown
---
name: polish
description: 润色选中的段落，保持原意，收紧句子
---

对给出的文字逐句润色：删掉冗余的词，把长句拆短，
保持原本的意思和语气不变。只输出润色后的文字。
```

使用技能有两种方式：

1. **直接调用**：在对话输入框中输入 `/`，从菜单里选；或者输入技能名再接上你的要求，比如 `/polish 再帮我看看这段`。
2. **直接提要求**（仅限支持工具调用的服务）：Textus AI 知道每个技能的名称和描述，当你的请求和某个技能对得上时，它会自己加载完整指令并照做。

技能和写作要求一样分两级：全局技能放在全局配置文件夹的 `skills/` 里（**设置 > Textus AI > 技能 > 导入技能…** 会把技能文件复制过去），项目技能放在 `.textus/skills/` 里（这是隐藏文件夹——在 macOS 的访达中按 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>.</kbd> 可以显示）。项目技能和全局技能同名时，以项目的为准。

### 内置技能

Textus 自带 19 个技能，覆盖常见的写作任务。`/` 菜单把它们分成四组：**写作**（接着写、描写人物或场景、对话润色、模仿文风）、**修改**（扩写、精简、调整语气、去 AI 味、翻译润色）、**检查**（校对、检查前后一致）和**文体**（写邮件、公文与通知、会议纪要、学术润色、社媒文案、起标题、总结摘要、设计主题）。输入 `/` 后从菜单中选择，或者直接输入它在任一界面语言中的名称：`/proofread`、`/校对` 和 `/校正` 调用的是同一个技能。你的请求与某个技能相符时，Textus AI 大多会自行选用；**扩写**、**精简**、**调整语气**和**总结摘要**则只在你主动调用时运行。**设计主题**按你的描述写一份编辑器主题 CSS，放在回复里：点回复下方的**使用此主题**即可安装并启用，也可以存成 .css 文件，再用**设置 > 编辑与外观 > 导入 CSS…**导入。

**设置 > Textus AI > 内置技能** 列出了全部技能。关掉开关，这个技能就会从 `/` 菜单中消失，Textus AI 也不再使用它。**自定义…** 会把技能复制到全局配置文件夹的 `skills/` 中并打开这份副本，你可以随意修改其中的说明；此后运行的就是你的副本。**还原** 会删除副本，恢复内置版本。你自己的技能如果与内置技能同名，会取代内置技能。

### 写作规范

**设置 > Textus AI > 写作辅助 > 写作规范** 决定 Textus AI 和语法检查遵循哪套标点、空格和数字规范。选择**自动**时，有国家标准的语言按国家标准处理（例如简体中文按 GB/T，日语按 JTF）；其他情况则沿用文档里已经占多数的写法，只指出前后不一致的地方。选定一套规范（例如简体中文的**小说**），这种语言的文档就按它来要求。

项目也可以单独指定：在文风档案（`.textus/style.md`）开头的两行 `---` 之间加一行 `conventions:`。对这个项目的文档，它优先于设置里的选择。

```markdown
---
conventions: zh-Hans-CN/fiction, en-GB/govuk
---
```

### 全局配置文件夹

**全局配置文件夹存放对所有文档生效的内容**：全局的 `agent.md` 和全局技能。它属于应用本身，不属于任何项目；**设置 > Textus AI > 全局配置文件夹 > 打开** 可以打开它。

```
agent/                ← 全局配置文件夹
├── agent.md          ← 全局写作要求
└── skills/
    └── outline.md    ← 一个全局技能
```

文风档案和资料库没有全局版本：它们描述的是某一部作品，所以属于项目。

### 什么时候用到什么

| | 对话 | 续写 | 语法检查 |
| --- | :---: | :---: | :---: |
| 项目文件（阅读、搜索、`@`） | ✓ | | |
| 文风档案 | ✓ | ✓ | |
| 被提到的资料库条目 | ✓ | ✓ | |
| 写作要求 | ✓ | | |
| Textus AI 记住的内容 | ✓ | | |
| 技能 | ✓ | | |
| 续写语气（设置） | | ✓ | |

- **先全局，后项目。** 两级的写作要求都会发送，项目的排在后面，冲突时以项目的为准；项目技能会替换同名的全局技能。
- **同一时间只有一个项目文件夹。** 只有它的 `.textus/` 有效：另选了项目文件夹后，文档旁边的 `.textus/` 不会被读取。
- **改完即生效。** 修改这些文件后，下一次请求就会用上新内容，无需重启（续写约十秒内生效）。

### 什么内容写在哪里？

- 文字应该读起来是什么样 → **文风档案**。
- 谁是谁、什么是什么 → **资料库**。
- 对话中 Textus AI 应该知道或始终遵守的事 → **写作要求**。
- 反复要做的同一类任务 → **技能**。
- 笔记、资料、前面的章节 → 放在**项目文件夹**里的普通文件，需要时 Textus AI 会自己去读。

## 关闭 Textus AI

在窗口栏右端的 **Textus AI** 按钮上点右键，可以暂停 Textus AI 1 小时，或者把它关闭。关闭期间，羽毛笔图标上会有一道斜线，点它可以重新开启；暂停满 1 小时后会自动恢复。**设置 > Textus AI > 开启 Textus AI**，以及可以在 **设置 > 快捷键** 里设定的快捷键，也能开启或关闭；iPhone 上它在菜单里。

关闭期间，从打开 Textus 起就不会向任何 AI 服务发送内容：没有续写、没有语法检查、没有对话，也不会记住什么。AI 面板、快速提问和右键菜单里的 AI 项目都会隐藏，正在生成的回复会停下。文档里已经提出的修改仍然保留，等你接受或拒绝。每项功能都保留自己的设置，重新开启 Textus AI 后照常生效。

## 隐私说明

文档内容、附加和 @ 引用的文件、你的写作要求、文风档案、被提到的资料库条目，以及 Textus AI 读取的项目文件，会随请求发送给你所选的服务；**从样本学习我的文风**会发送你选中的样本。打开联网搜索时，搜索内容会发给你所选的服务，或发给设置里显示的搜索服务；Textus AI 读取的网页从这台电脑下载。不需要时在设置里关掉对应功能即可。
