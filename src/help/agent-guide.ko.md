# Textus AI 기능 가이드

Textus에는 글쓰기를 위해 만든 AI인 Textus AI가 들어 있습니다. 이어 쓰기, 문법 검사, 그리고 문서를 읽고 고쳐 주는 대화를 제공합니다. 이 가이드에서는 서비스를 연결하는 방법과 AI 기능, 그리고 프로젝트 폴더, 문체 프로필, 라이브러리, 글쓰기 지침, 스킬로 Textus AI를 나만의 글쓰기 도우미로 만드는 방법을 설명합니다.

## 서비스 연결

1. **설정 > Textus AI**를 열고 **연결 > 제공업체**에서 사용할 서비스를 선택합니다.
2. **로그인 및 인증 정보**를 펼치고, 그 서비스가 지원하는 방식에 따라 계정으로 로그인하거나 API 키를 입력합니다.
3. **사용자 지정 엔드포인트**(로컬 모델이나 프록시 등 OpenAI 호환 서버라면 무엇이든)를 쓰려면 기본 URL, 필요하면 키, 모델 이름을 입력하고 저장합니다.
4. **글쓰기 보조**에서 보조 모델을, **Textus AI 채팅**에서 채팅 모델을 고릅니다.

로그인은 브라우저에서 진행됩니다. 이미지, 웹 검색, 문서 수정을 쓸 수 있는지는 선택한 서비스와 모델에 따라 다릅니다.

기본 제공 모델 목록에는 제공업체마다 기본 모델만 들어 있습니다(Anthropic은 채팅에 Claude Sonnet 5.5, 이어 쓰기와 문법 검사에 Claude Haiku 5.5). **연결** 아래 모델 목록 행에서 **모델 가져오기**를 누르면 제공업체의 현재 목록을 불러와 그중 어떤 모델이든 고를 수 있습니다.

아래 단축키는 macOS 표기입니다. Windows와 Linux에서는 Cmd를 Ctrl로, Option을 Alt로 바꿔 읽으세요. 단축키를 바꿨다면 **설정 > 단축키**에서 현재 단축키를 확인할 수 있습니다.

## AI 기능

### 1. 이어 쓰기

입력하는 동안 커서 위치에 회색으로 이어 쓴 글이 나타납니다. <kbd>Tab</kbd> 키를 누르면 전부 수락하고, <kbd>Cmd</kbd>+<kbd>→</kbd>를 누르면 다음 단어만 받아들이고 나머지는 제안으로 남겨 둡니다. <kbd>Esc</kbd> 키를 누르면 사라집니다. 최소 글자 수 제한이 없어서 문서의 첫 문장부터 바로 작동합니다.

<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>Space</kbd>나 오른쪽 클릭 메뉴로 직접 요청하면(커서가 문단 끝에 있어야 합니다) 더 긴 이어 쓰기를 최대 세 가지 대안과 함께 받습니다. <kbd>Option</kbd>+<kbd>[</kbd> / <kbd>Option</kbd>+<kbd>]</kbd>로 대안을 차례로 넘겨 봅니다.

**설정 > Textus AI > 글쓰기 보조**에서 **이어 쓰기 어조**(문서에 맞게 / 격식 있게 / 편하게 / 학술적으로 / 간결하게)를 고를 수 있습니다. 문서가 문체 프로필이나 라이브러리가 있는 프로젝트에 속하면(아래 **Textus AI를 나에게 맞추기** 참고) 이어 쓰기도 그것을 따릅니다.

### 2. 문법 검사

문제가 있을 수 있는 부분에 밑줄이 그어집니다. 밑줄 위에 포인터를 올리거나 커서를 그 안으로 옮기면 설명이 나타납니다. **적용**(또는 커서를 그 위에 두고 <kbd>Option</kbd>+<kbd>Enter</kbd>)을 누르면 수정이 반영되고, **무시**를 누르면 밑줄이 사라집니다. <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>G</kbd>를 누르면 현재 문단을 바로 검사합니다.

### 3. AI 패널

전체 대화는 편집기 오른쪽의 패널에서 이루어집니다. 제목 표시줄 오른쪽 끝의 **Textus AI** 버튼(로봇 아이콘)이나 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>L</kbd>로 열고 닫습니다.

- **문서마다 대화 하나**: 탭마다 대화가 따로 있으며, 탭을 바꾸면 패널도 함께 바뀝니다. 패널 상단의 **새 대화**를 누르면 처음부터 다시 시작합니다(결정하지 않은 수정이 남아 있으면 먼저 묻습니다).
- **모드**: 입력창에는 세 가지 모드가 있습니다. **쓰기**는 문서에 새 글(이어 쓰기, 새 문단이나 절)을 덧붙이기만 하며, 텍스트를 선택했으면 선택 영역 뒤에 씁니다. **검토**는 질문에 답하고 의견을 나누며 댓글을 달 뿐 문서를 바꾸지 않습니다. **수정**은 이미 있는 글을 고칩니다. 쓰기와 수정의 모든 변경은 제안이며, 적용하거나 거절할 수 있습니다. 패널은 **설정 > Textus AI > Textus AI 채팅 > 기본 모드**에서 정한 모드로 시작합니다.
- **@ 멘션**: 입력창에 `@` 기호를 입력하면 프로젝트 폴더의 텍스트 파일을 골라 메시지에 첨부할 수 있습니다.
- **파일 첨부**: 입력창 왼쪽의 **+** 버튼으로 PDF, Word 문서, PowerPoint 프레젠테이션, 스프레드시트, EPUB 전자책, RTF·HTML 파일, 이미지, 일반 텍스트 파일을 그 메시지에 첨부합니다. 이미지가 아닌 파일은 기기에서 텍스트로 추출되어 메시지에 담겨 전송되고, 이미지는 이미지를 볼 수 있는 제공업체에 실제 이미지로 전송됩니다(볼 수 없는 제공업체는 이미지를 조용히 빼지 않고 미리 알려 줍니다). 긴 파일은 일부만 전송되며, 그럴 때는 첨부 항목에 “(일부 생략)”이라고 표시됩니다.
- **웹 검색**: **설정 > Textus AI > Textus AI 채팅**에서 켜 두면(지원하는 제공업체만) 요청에 필요할 때 Textus AI가 스스로 웹을 검색합니다.
- **기록**: AI 패널 위쪽의 **기록** 버튼(시계 아이콘)에 지난 대화가 폴더별로 표시됩니다. 대화를 클릭하면 그 대화의 문서와 함께 다시 열어 이어 갈 수 있습니다.
- **오류**: 요청이 실패하면 채팅에서 제공업체가 보낸 메시지 위에 어떤 종류의 문제인지, 무엇을 하면 되는지(키 확인, 잠시 기다리기, 다른 모델 선택)를 알려 줍니다.

패널 상단의 **별도 창에서 열기**를 누르면 대화를 독립된 창으로 옮깁니다. 보조 모니터에서 쓰기 좋습니다. 이 창은 지금 작업 중인 곳을 따라갑니다. 탭이나 창을 바꾸면 문서, 제목, 선택 영역이 함께 바뀌고, 제안하는 수정은 실제로 편집 중인 파일에 들어갑니다. 별도 창은 편집기 창마다 하나뿐이며, 창 상단의 **📌** 버튼을 누르면 편집기 위에 계속 표시됩니다.

### 4. 빠른 질문

<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>K</kbd>(또는 오른쪽 클릭 > AI에게 묻기…)를 누르면 지금 있는 문단 바로 아래에 작은 채팅 막대가 열립니다. 막대는 문서 안에 자리를 잡고, 아래 텍스트를 가리지 않고 밀어 내립니다. 열 때 선택한 텍스트가 있었다면 그 선택 영역도 함께 전달됩니다. 빠른 질문은 **수정** 모드로 열립니다. 보통 고치고 싶은 부분에서 열기 때문입니다(“이 부분을 줄여 주세요”). 모드 선택에서 한 번만 클릭하면 쓰기나 검토 모드로 바꿀 수 있습니다.

- **단축키를 다시 누르면**: 막대가 열려 있을 때 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>K</kbd>를 누르면 커서가 입력창으로 이동하고, 입력창에서 한 번 더 누르면 막대가 닫힙니다. 막대 어디에서든 <kbd>Esc</kbd> 키를 눌러도 닫히며, 커서는 문서로 돌아갑니다. 결정하지 않은 수정이 남아 있으면 닫기 전(또는 새 대화를 시작하기 전)에 먼저 묻습니다.
- 빠른 질문은 패널과 별개인 짧은 대화를 따로 이어 가며, 기록에 저장되지 않습니다. 패널이 열려 있어도 열립니다. 모서리의 **전체 대화에서 계속하기** 버튼을 누르면 지금까지의 대화를 AI 패널로 넘겨 그곳에서 이어 가고 저장합니다. **설정 > Textus AI > 고급 > 전체 대화를 별도 창에서 열기**를 켜 두면 대신 별도 창으로 보냅니다.

### 5. 문서 안의 수정

채팅은 문서에 직접 쓰지 않습니다. 도구 호출을 지원하는 제공업체에 문서 수정을 요청하면, 변경마다 적용될 자리에 바로 제안으로 표시됩니다. 지워질 텍스트에는 취소선이 그어지고, 새 텍스트는 초록색으로 삽입되어 보입니다. 수락하기 전까지는 문서가 전혀 바뀌지 않으며, 수락한 수정은 <kbd>Cmd</kbd>+<kbd>Z</kbd>로 한 번에 되돌릴 수 있습니다.

- **수락 / 거부**: 수정 옆에 뜨는 막대, 패널의 제안 카드, 또는 키보드로 할 수 있습니다. <kbd>Cmd</kbd>+<kbd>Return</kbd>을 누르면 수락하고, 커서를 수정 위에 두고 <kbd>Cmd</kbd>+<kbd>Delete</kbd>를 누르면 거부합니다. 한 답변에 제안이 여러 개 있으면 동시에 미리 보기로 표시되며, ‹›로 제안 사이를 오갈 수 있고 모두 수락이나 모두 거부로 한꺼번에 처리할 수도 있습니다.
- **이유**: 제안 카드마다 Textus AI가 그렇게 바꾼 이유가 적혀 있습니다.
- **일부 문장만**: 제안이 여러 문장을 고쳐 쓰면 카드에 **문장 선택(N)**이 나타납니다. 원하는 문장에만 체크하면 수락 버튼이 **N개 중 K개 수락**으로 바뀌고, 누르면 체크한 문장만 적용됩니다.
- **커서 위치에**: 아무것도 선택하지 않았을 때도 Textus AI는 커서가 어디 있는지 알기 때문에, “여기에 연결 문장을 써 주세요”라고 하면 정확히 그 자리에 삽입합니다.
- **수정 대신 댓글**: 검토를 부탁하면(“여기서 약한 부분은 어디인가요?”) Textus AI가 본문을 바꾸지 않고 해당 부분에 댓글을 답니다. 댓글 카드의 **문서에서 보기**를 누르면 그 댓글이 가리키는 부분이 선택됩니다.

## Textus AI를 나에게 맞추기

Textus AI는 숨겨진 설정이 아니라 평범한 Markdown 파일 몇 개를 보고 사용자와 작업을 파악합니다. 파일마다 맡은 일이 하나씩 있습니다:

| 개념 | 무엇인가 | 위치 |
| --- | --- | --- |
| **프로젝트 폴더** | Textus AI가 작업하고 읽을 수 있는 폴더 | 문서가 있는 폴더 또는 직접 고른 폴더 |
| **문체 프로필** | 글 쓰는 방식 | `.textus/style.md` |
| **라이브러리** | 인물, 장소, 용어에 관한 사실 | `.textus/library/` |
| **글쓰기 지침** | 모든 대화에 적용되는 고정 규칙 | `agent.md`(전역 및 프로젝트별) |
| **AI가 기억한 것** | Textus AI가 대화에서 기억해 두는 것 | `.textus/memory/` 및 전역 설정 폴더의 `memory/` |
| **스킬** | `/이름`으로 불러 쓰는 재사용 지침 | `skills/`(전역 및 프로젝트별) |
| **전역 설정 폴더** | 모든 문서에 적용되는 것 | 앱의 설정 폴더 |

아래에서 ‘대화’는 AI 패널과 빠른 질문을 뜻합니다. 프로젝트 하나를 한눈에 보면 다음과 같습니다:

```
내 소설/                  ← 프로젝트 폴더
├── 1장.md               ← 편집 중인 문서
├── 메모/
│   └── 연표.md           ← Textus AI가 읽을 수 있는 참고 자료
└── .textus/              ← 프로젝트 자체 설정
    ├── style.md         ← 문체 프로필
    ├── agent.md         ← 이 프로젝트의 글쓰기 지침
    ├── library/
    │   ├── 린완.md       ← 인물, 장소, 용어마다 항목 하나
    │   └── 하버 시티.md
    └── skills/
        └── polish.md    ← 파일 하나에 스킬 하나
```

`.textus/` 폴더와 그 안의 파일은 프로젝트 메뉴에서 처음 필요할 때 자동으로 만들어집니다. 직접 추가하는 것은 프로젝트 스킬뿐입니다. 이 파일들 어디에서든 `<!-- -->` 주석 안의 텍스트는 자신을 위한 메모이며 전송되지 않습니다.

### 프로젝트 폴더

**프로젝트 폴더는 Textus AI가 작업하는 폴더입니다.** 기본적으로는 편집 중인 문서가 있는 폴더, 또는 그 위에서 `.textus/` 폴더가 있는 가장 가까운 폴더입니다. 그래서 `novel/part-1/`에 있는 장은 `novel/`에 속합니다. 문서를 저장하면 그 폴더가 프로젝트 폴더가 됩니다.

- Textus AI는 이 폴더의 파일을 나열하고, 이름으로 찾고, 읽고, 검색해서, 인물이 앞서 나온 장면이나 용어, 메모를 찾습니다. 대상은 16 MB까지의 텍스트 파일(Markdown, 일반 텍스트 등. 긴 파일은 나누어 읽습니다)과 PDF, Word, PowerPoint, 스프레드시트, EPUB, RTF 파일의 텍스트입니다. 이미지를 볼 수 있는 제공업체라면 이 폴더의 PNG, JPEG, GIF, WebP 이미지(한 장에 6 MB까지)도 봅니다. 숨김 파일과 숨김 폴더, `.gitignore`나 `.ignore` 파일이 제외하는 항목(사이드바의 파일 검색과 같음), 빌드 및 의존성 폴더(`node_modules` 등), 텍스트 층이 없는 스캔 PDF는 제외됩니다.
- 채팅 입력창에 `@` 기호를 입력하면 이 폴더의 파일을 메시지에 첨부할 수 있습니다.
- 이 폴더 안의 `.textus/` 폴더에 프로젝트의 문체 프로필, 라이브러리, 글쓰기 지침, 스킬이 들어 있습니다.

AI 패널 상단 바로 아래의 막대에 프로젝트 폴더 이름이 표시되고, 이를 클릭하면 **프로젝트 메뉴**가 열립니다. 참고 자료가 초안과 다른 곳에 있다면 이 메뉴의 **프로젝트 폴더 선택…**을 쓰세요(**설정 > Textus AI > 프로젝트 폴더**에서도 됩니다). 고른 폴더는 **문서가 있는 폴더 사용**을 다시 선택할 때까지 저장하지 않은 초안을 포함한 모든 문서에 쓰입니다.

> [!TIP]
> 초안은 `논문/초안/`에, 인터뷰 메모는 `논문/자료/`에 있나요? `논문/`을 프로젝트 폴더로 고르면 `초안/2장.md`를 쓰는 동안 Textus AI가 `자료/인터뷰.md`를 읽을 수 있습니다.

Textus AI가 읽는 모든 것은 프로젝트 폴더 안에 있어야 합니다. `..`, 절대 경로, 폴더 밖을 가리키는 링크는 거부됩니다. 폴더를 고르지 않았다면 저장하지 않은 초안에는 프로젝트 폴더가 없으며, 범위가 너무 넓은 폴더(홈 폴더나 드라이브 전체)는 거부됩니다.

### 문체 프로필 — ‘내 문체 학습’

**문체 프로필은 글 쓰는 방식을 설명합니다.** 이어 쓰기와 수정이 내가 쓴 글처럼 읽히도록 어조, 문장 리듬, 어휘, 문장 부호, 절대 하지 않는 것을 적습니다. 프로젝트의 모든 문서에서 Textus AI는 대화할 때, 이어 쓰기는 입력하는 동안 이 프로필을 따릅니다. 실제로는 `.textus/style.md` 파일입니다.

만드는 방법은 두 가지이며, 둘 다 프로젝트 메뉴에 있습니다:

- **샘플로 내 문체 학습…**: 직접 쓴 글 파일을 몇 개(최대 여덟 개) 고릅니다. Textus AI가 이를 분석해 어조, 문장과 리듬, 어휘, 문장 부호와 서식, 구성, 하지 않는 것, 그리고 예시로 짧은 인용 몇 개를 담은 프로필 초안을 쓰고 새 탭에서 엽니다. 읽어 보고, 고치고, 보태세요. 이제 내 것입니다. 다시 학습하면 이전 프로필은 `style.previous.md`로 남습니다.
- **문체 프로필 만들기**: 빈 틀에서 시작해 직접 씁니다.

프로필이 생기면 폴더 이름 옆의 **문체** 버튼으로 열 수 있습니다.

```markdown
# 문체 프로필

## 문장과 리듬
- 문장은 짧게, 40자를 넘는 일은 드물게.
- 문단은 구체적인 장면으로 시작하고 요점은 그다음에.

## 금지 사항
- 느낌표를 쓰지 않는다. ‘갑자기’를 쓰지 않는다.
```

형용사보다 확인할 수 있는 구체적인 항목이 더 효과적입니다. ‘간결하게’ 대신 ‘문장은 짧게, 40자를 넘는 일은 드물게’처럼 쓰세요. 분량은 한두 쪽 정도로 하세요. 처음 6,000자까지만 사용됩니다. 설정의 **이어 쓰기 어조**도 함께 적용됩니다. 문체 프로필에 이미 글의 어조를 적었다면 *문서에 맞게*로 두세요.

### 라이브러리

**라이브러리에는 일관되게 유지해야 하는 사실을 둡니다.** 인물, 장소, 용어마다 Markdown 파일을 하나씩 `.textus/library/`에 둡니다. 프로젝트 메뉴의 **새 라이브러리 항목…**을 누르면 이름을 묻고 새 항목을 엽니다. **라이브러리** 표시에 항목 수가 나옵니다.

```markdown
---
name: 린완
aliases: [완, 린 선생]
include: detected
---

주인공. 32세. 하버 시티의 중학교에서 국어를 가르친다.
왼손잡이. 오빠 이야기는 절대 하지 않는다.
```

항목을 직접 첨부할 필요는 없습니다. `include: detected`(기본값)인 항목은 이름이나 별칭이 나올 때마다 Textus AI에게 전달됩니다. 대화 중에는 메시지나 문서에서, 이어 쓰기 중에는 커서 주변 텍스트에서 찾습니다. `always`는 모든 요청에 함께 보내고, `never`는 보내지 않습니다. 언급되지 않은 항목은 아무 비용도 들지 않으므로 라이브러리는 프로젝트에 필요한 만큼 얼마든지 늘릴 수 있습니다.

### 글쓰기 지침(agent.md)

**글쓰기 지침은 모든 대화에 함께 전송되는 고정 규칙입니다.** 프로젝트가 무엇인지, 어느 언어로 답할지, 표기와 용어, Textus AI가 항상 하거나 절대 하지 말아야 할 일을 적습니다. `agent.md`라는 파일에 두 단계로 둡니다:

- **전역**(모든 문서): **설정 > Textus AI > 글쓰기 지침(agent.md) > agent.md 편집**.
- **프로젝트**(한 프로젝트의 문서): `.textus/agent.md`. 프로젝트 메뉴의 **프로젝트 글쓰기 지침 편집**으로 엽니다.

두 파일 모두 탭에서 열리며, 맨 앞에 주석으로 짧은 안내가 들어 있습니다. 둘 다 있으면 Textus AI는 두 지침을 모두 받습니다. 전역 지침이 먼저, 프로젝트 지침이 그다음이며, 서로 다르면 프로젝트 지침이 우선합니다.

```markdown
1930년대 상하이를 무대로 한 추리 소설이며, 린완이 1인칭으로 이야기한다.
소설은 중국어로 쓰지만 답은 항상 한국어로 한다.
‘하버 시티’로 띄어 쓰고 ‘하버시티’로 붙여 쓰지 않는다.
```

글쓰기 지침은 대화에만 적용됩니다. 이어 쓰기는 이 지침을 읽지 않고 문체 프로필과 라이브러리를 따릅니다.

### Textus AI가 기억하는 것

**Textus AI는 내가 요청한 것과 내 글쓰기 방식을 기억합니다.** 파일을 직접 쓸 필요가 없습니다. 한 번의 요청을 넘어 지켜야 할 것(‘항상 존댓말로’, ‘줄표는 쓰지 않기’, 두 번이나 고쳐야 했던 수정)이나 등장인물이 누구인지 같은 작품에 관한 사실을 말하면, 이를 기억해 두었다가 이후 대화에서 따릅니다. 그때마다 답변 아래에 무엇을 어디에 기억했는지 알려 주는 줄이 나타납니다. **실행 취소**로 되돌리고, **개인으로 옮기기**나 **프로젝트로 옮기기**로 옮길 수 있습니다.

- **이 프로젝트**: 이 작품에 관한 것은 `.textus/memory/`에 둡니다. 인물, 장소, 용어에 관한 사실은 라이브러리에 들어갑니다.
- **모든 프로젝트**: 일반적인 습관은 전역 설정 폴더의 `memory/`에 둡니다. 프로젝트 폴더가 없으면 모두 여기에 들어갑니다.

AI 패널의 **기억** 탭에는 **AI가 기억한 것** 아래에 모든 항목이 나열되며, 각각 언제 어느 대화에서 기억했는지도 표시됩니다. **편집**으로 열고 **삭제**로 지웁니다. 직접 쓴 글쓰기 지침과 충돌하면 글쓰기 지침이 우선하며, Textus AI는 `agent.md`나 문체 프로필을 절대 바꾸지 않습니다. 기억이 너무 많아 다 보낼 수 없으면 가장 오래된 것부터 빠지고, 기억 탭에 그 사실이 표시됩니다. **설정 > Textus AI > 자동으로 기억**에서 끌 수 있습니다.

### 스킬(/이름)

**스킬은 이름이 붙은 재사용 지침입니다.** ‘다듬기’, ‘개요 짜기’, ‘인용 확인’ 같은 작업을 Markdown 파일 하나에 담습니다. 맨 위에 이름과 한 줄 설명을, 그 아래에 전체 지침을 적습니다.

```markdown
---
name: polish
description: 선택한 부분을 의미는 그대로 두고 더 간결하게 다듬는다
---

주어진 텍스트를 한 문장씩 다듬는다. 군더더기 단어를 덜어 내고,
너무 긴 문장은 나누고, 원래 의미와 어조는 그대로 둔다.
다듬은 텍스트만 출력한다.
```

스킬은 두 가지 방법으로 씁니다:

1. **불러 쓰기**: 채팅 입력창에 `/`를 입력하고 메뉴에서 고르거나, 스킬 이름 뒤에 요청을 이어 씁니다: `/polish 이 부분도 다시 봐 주세요`.
2. **그냥 부탁하기**(도구 호출을 지원하는 제공업체만): Textus AI는 모든 스킬의 이름과 설명을 알고 있어서, 요청이 어떤 스킬과 맞으면 스스로 전체 지침을 불러와 따릅니다.

스킬은 글쓰기 지침과 같은 두 단계에 둡니다. 전역 스킬은 전역 설정 폴더의 `skills/` 폴더에(**설정 > Textus AI > 스킬 > 스킬 가져오기…**로 스킬 파일을 그곳에 복사할 수 있습니다), 프로젝트 스킬은 `.textus/skills/`에 둡니다(숨김 폴더입니다. macOS Finder에서는 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>.</kbd>를 누르면 보입니다). 이름이 같은 프로젝트 스킬이 있으면 전역 스킬 대신 쓰입니다.

### 내장 스킬

Textus에는 자주 하는 글쓰기 작업을 위한 스킬 19개가 들어 있습니다. `/` 메뉴에서는 **쓰기**(다음 장면 쓰기, 인물·장면 묘사, 대사 다듬기, 문체 따라 쓰기), **고치기**(늘려 쓰기, 간결하게, 어조 바꾸기, AI 티 없애기, 번역 다듬기), **검사**(교정, 설정 오류 확인), **문서 양식**(이메일 쓰기, 공문서·공지, 회의록, 논문 다듬기, SNS 게시물, 제목 짓기, 요약, 테마 만들기)의 네 묶음으로 나뉩니다. `/`를 입력해 메뉴에서 고르거나, 앱의 어느 언어로든 이름을 입력하면 됩니다. `/proofread`, `/교정`, `/校对`는 모두 같은 스킬을 부릅니다. 요청이 스킬과 맞으면 Textus AI가 대부분의 스킬을 스스로 골라 씁니다. 다만 **늘려 쓰기**, **간결하게**, **어조 바꾸기**, **요약**은 직접 불렀을 때만 실행됩니다. **테마 만들기**는 설명에 맞는 편집기 테마를 CSS로 답변에 씁니다. 답변 아래의 **이 테마 사용**을 누르면 설치되어 바로 적용되고, .css 파일로 저장해 **설정 > 편집기 및 모양 > CSS 가져오기…**로 가져올 수도 있습니다.

**설정 > Textus AI > 내장 스킬**에 모든 스킬이 나와 있습니다. 스위치를 끄면 그 스킬은 `/` 메뉴에서 사라지고 Textus AI도 더는 쓰지 않습니다. **사용자 지정…**은 스킬을 전역 설정 폴더의 `skills/`에 복사하고 그 사본을 열어 주므로, 지침을 마음대로 고칠 수 있습니다. 그 뒤로는 사본이 대신 실행됩니다. **초기화**는 사본을 지우고 내장 버전으로 되돌립니다. 내장 스킬과 이름이 같은 내 스킬이 있으면 내 스킬이 대신 쓰입니다.

### 표기 규칙

**설정 > Textus AI > 글쓰기 보조 > 표기 규칙**에서 Textus AI와 문법 검사가 따를 문장 부호, 띄어쓰기, 숫자 표기 규칙을 고릅니다. **자동**으로 두면 국가 규범이 있는 언어는 그 규범을 따르고(예: 한국어는 국립국어원 어문 규범, 일본어는 JTF), 그 밖에는 문서에서 이미 더 많이 쓰인 표기를 따르면서 서로 어긋나는 곳만 짚어 줍니다. 규칙을 하나 고르면(예: 한국어의 **공문서**) 그 언어로 쓴 문서는 그 규칙에 맞춰 검사합니다.

프로젝트마다 따로 정할 수도 있습니다. 문체 프로필(`.textus/style.md`) 맨 위의 `---` 두 줄 사이에 `conventions:` 줄을 넣으면, 그 프로젝트의 문서에서는 설정보다 이 값이 우선합니다.

```markdown
---
conventions: zh-Hans-CN/fiction, en-GB/govuk
---
```

### 전역 설정 폴더

**전역 설정 폴더에는 모든 문서에 적용되는 것을 둡니다.** 전역 `agent.md`와 전역 스킬입니다. 이 폴더는 어느 프로젝트가 아니라 앱에 속하며, **설정 > Textus AI > 전역 설정 폴더 > 보기**로 열 수 있습니다.

```
agent/                ← 전역 설정 폴더
├── agent.md          ← 전역 글쓰기 지침
└── skills/
    └── outline.md    ← 전역 스킬
```

전역 문체 프로필이나 전역 라이브러리는 없습니다. 둘 다 하나의 작품을 설명하므로 프로젝트에 속합니다.

### 언제 무엇이 적용되나

| | 대화 | 이어 쓰기 | 문법 검사 |
| --- | :---: | :---: | :---: |
| 프로젝트 파일(읽기, 검색, `@`) | ✓ | | |
| 문체 프로필 | ✓ | ✓ | |
| 언급된 라이브러리 항목 | ✓ | ✓ | |
| 글쓰기 지침 | ✓ | | |
| Textus AI가 기억한 것 | ✓ | | |
| 스킬 | ✓ | | |
| 이어 쓰기 어조(설정) | | ✓ | |

- **전역 다음에 프로젝트.** 두 단계의 글쓰기 지침이 모두 전송되고 프로젝트 지침이 마지막에 오며, 충돌하면 프로젝트 지침이 우선합니다. 이름이 같은 전역 스킬은 프로젝트 스킬로 대체됩니다.
- **프로젝트 폴더는 한 번에 하나.** 그 폴더의 `.textus/`만 적용됩니다. 프로젝트 폴더를 직접 골랐다면 문서 옆의 `.textus/`는 읽지 않습니다.
- **다시 시작할 필요 없음.** 이 파일들을 고치면 다음 요청부터 새 내용이 쓰입니다(이어 쓰기에는 10초 정도 안에 반영됩니다).

### 어떤 파일에 무엇을 쓸까?

- 글이 어떻게 읽혀야 하는지 → **문체 프로필**
- 누가 누구이고 무엇이 무엇인지 → **라이브러리**
- 대화에서 Textus AI가 알아야 하거나 항상 해야 하는 것 → **글쓰기 지침**
- 거듭 부탁하는 작업 → **스킬**
- 메모, 자료 조사, 앞선 장 → **프로젝트 폴더**의 일반 파일. 요청에 필요하면 Textus AI가 읽습니다.

## 개인정보에 관한 안내

문서, 첨부하거나 @ 멘션한 파일, 글쓰기 지침, 문체 프로필, 언급된 라이브러리 항목, Textus AI가 읽은 프로젝트 파일은 요청할 때마다 선택한 제공업체로 전송됩니다. **내 문체 학습**을 쓰면 고른 샘플이 전송됩니다. 웹 검색은 그 제공업체의 서버에서 실행됩니다. 원하지 않는 기능은 설정에서 끄세요.
