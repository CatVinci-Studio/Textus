# Versions

Which Textus each part of the plugin API needs. Set `engines.textus` to
the newest one you use (`">=1.3.10"`); Textus outside the range doesn't
load the plugin. To use something newer only where it exists, check it
instead: `if (textus.dates) …`, or compare `textus.env.apiVersion` as
numbers ("1.10" is after "1.9").

## What stays

- Every Textus release that adds to the API raises its minor version
  (1.6 → 1.7) and adds a row here; the call's "From 1.x" note says when.
- What is in textus.d.ts without a "Preview" note is stable: it keeps its
  name, arguments and answers. A plugin written for 1.0 still runs.
- A better name or shape comes in beside the old one, which keeps
  working. The old one is marked "Deprecated" in textus.d.ts with what to
  use instead, and stays until Textus's next minor release: deprecated
  in 1.4, it can go in 1.5. It goes only with a row here saying so.
- Lines count from 0 in every `Location` and in the index
  (`metadata.*`); the only line from 1 is a search hit's `line`, kept for
  the plugins that read it - use its `location`.
- Events are `onDid…` (after) or `onWill…` (before, a chance to change
  it); `register…` gives back something to `dispose()`.
- A new `register…` takes the plugin's own `id` and an object with its
  `label` and functions. An id made of a plugin's and its own is
  `<plugin id>#<id>`; `history.sources()`'s `<plugin id>/<source>` stays
  as it shipped.
